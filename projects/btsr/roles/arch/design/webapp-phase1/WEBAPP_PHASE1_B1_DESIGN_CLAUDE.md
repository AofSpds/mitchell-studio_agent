## 1. 한 줄

어느 화면에서나 여는 「Feedback」 시트 → 건의는 **맥의 `data/suggestions/`에 먼저 쌓임**(git 밖) → 검토 도구가 손님 정보 꼴을 걸러 보이고 → 사람이 확인한 것만 저장소 맨 위 **`suggestions/`**로. 화면 글은 **한 장의 말 표**대로 바꾸고, 아직 손 인계에 묶인 글은 쉬운 말로만 바꾼 뒤 그 인계를 없애는 묶음(2·5·6)에서 지운다 — 남은 글은 시험의 '남은 말 목록'으로 센다.

## 2. 건의함 (R1.1 · R1.2)

### 2-1 화면 (화9)

- 머리(`<header class="brand">`, app.html:181) 오른쪽에 「Feedback」 단추 + 한국어 한 줄 "건의하기". 머리를 `position: sticky; top: 0`으로 바꿔 어느 화면 · 어느 스크롤에서나 보이게 한다(지금은 스크롤하면 사라짐). 탭은 넷 그대로(4-1 :309).
- 누르면 기존 시트(`openSheet`, app.html:713)에: 알약 셋 **안 돼요 · 이랬으면 해요 · 이건 좋아요**(하나 골라야 보내기 켜짐) · 글 칸(1000자, `REQUEST_MAX`) · "손님 이름·전화번호는 쓰지 마세요" · 「보내기」. 그림 붙이기 없음(화-마).
- 저절로 붙는 것: 보던 화면(`v-up`/`v-jobs`/`v-job`/`v-post`/`v-man`) · 작업 화면이면 작업 id와 지금 단계 · 브라우저 시각. Helpdesk의 `hdText()`(app.html:689-695)와 같은 꼴로 모으되 **작업 제목은 넣지 않는다**(제목에 손님 정보가 들 수 있음 — 4-1 :316).
- 작업 화면에서 열면 맨 위 한 줄: "이 영상을 고치려면 작업 화면의 「고칠 점」을 눌러 주세요" (묶음 6에서 「AI에게 고치기」로 바뀌면 그 이름으로).
- 보낸 뒤 toast "받았어요. 개발자가 읽어요." 시트 아래 「내가 보낸 건의」: 최근 10건의 날짜 · 갈래 · 첫 줄. 처리 상태는 보이지 않음(1차 밖).

### 2-2 서버

- `POST /api/suggest` — `reel_api.handle_post` 꼴(:308-349) 그대로. `{kind, text, view, job?, step?, client_at}`.
  - `kind` ∈ `broken`(안 돼요) · `wish`(이랬으면 해요) · `good`(이건 좋아요) — 이 목록 밖은 400. `text` 1–1000자. `view` ∈ 다섯 화면 id. `job`은 있는 작업 id일 때만 받음(없으면 빼고 저장).
  - 저장: `data/suggestions/inbox/<YYYY-MM-DD_HHMMSS>_<kind>[_n].md` — `os.O_EXCL`로 새 이름(reel_api :210-217 꼴), 덮어쓰지 않음. 서버 시각은 `now_kst()`.
  - 파일 꼴: 맨 위 YAML(`id` · `kind` · `received_at` · `view` · `job` · `step` · `client_at`) + 빈 줄 + 글 그대로.
- `GET /api/suggest` — 최근 10건 `[{id, kind, received_at, first_line}]` (첫 줄 60자까지).
- 주소 이름은 `/api/suggest`. `/api/feedback`(server :487 · :550-565, 옛 「고칠 점」 자리)는 이름이 겹치므로 쓰지 않고 손대지 않는다.
- `data/`는 이미 git 무시(.gitignore :7) → 맥에 쌓인 건의는 저장소에 저절로 들어가지 않는다. 서버에 git 명령을 넣지 않는다.
- 작업별 「고칠 점」(`/api/job/fix` → `data/working/<작업>/feedback/`)과 자리 · 주소 · 화면이 모두 달라 섞이지 않는다(R1.1 · 다-요27).

### 2-3 깃헙으로 — 검토 도구 `app/webapp/suggest.py` (R1.2)

명령줄 도구(표준 라이브러리만). 개발자 또는 개발자가 시킨 맥 세션이 돌린다.

| 명령 | 하는 일 |
|---|---|
| `suggest.py list` | inbox에 쌓인 것 목록 + 건마다 '손님 정보 꼴' 표시 |
| `suggest.py show <id>` | 글 전체와 걸린 자리 |
| `suggest.py publish <id> [--reviewed]` | 걸린 것이 없으면, 또는 사람이 보고 `--reviewed`를 주면 → 저장소 `suggestions/<YYYY-MM>/<id>.md`로 복사(글은 그대로, YAML에서 `job`·`client_at`은 뺌) → inbox 파일을 `data/suggestions/published/`로 옮김 |
| `suggest.py hold <id> --why "…"` | 올리지 않을 것 → `data/suggestions/held/` (지우지 않음) |

- '손님 정보 꼴'(자동 검사 — 사람 확인을 돕는 것, 대신하지 않음): 전화번호(`01[016-9]` 다음 숫자 7–8개, 하이픈 · 띄어쓰기 허용) · 9자리 넘는 숫자 줄 · 메일 주소 · 'OOO 님/고객/손님' 앞의 한글 이름 꼴. 걸리면 `publish`는 `--reviewed` 없이는 멈춘다.
- git add · commit · push는 도구가 하지 않는다 — 사람이(또는 시킨 세션이) 제품 저장소 규칙대로. 도구는 마지막에 해야 할 명령 한 줄만 보인다.
- 저장소 맨 위 `suggestions/README.md`: 이 폴더가 무엇인지, 파일 꼴, 갈래 셋, "손님 정보는 올리지 않음" — 영문 폴더 이름(한알 「건의함 폴더를 영문으로 하나 만드시면 됩니다.」).
- **물음 6(누가 거르는지)과의 관계:** 위 길은 PLN 요구의 권고 1(맥에 쌓고 개발자가 보고 올림)이다. 답이 2(바로 올림)여도 저장 · 자동 검사 · 폴더 꼴은 그대로 쓰고, '누가 `publish`를 부르는지'만 바뀐다(서버가 보낼 때 부르고 push까지). 그래서 묶음 1은 답 전에 만들어도 되고, 답이 2이면 그 몫만 더한다.
