## 3. 개발자에게 닿기 — `suggestions/` push (R5.7, 결정 32)

- `to = dev`가 되면 서버가 **글 파일 하나** `suggestions/dev/<YYYY-MM-DD_HHMM>_<작업 id>.md`를 쓴다(1.1판: **파일 이름은 작업 id만** — 작업 제목은 접수 뒤 손님 이름을 품을 수 있어 쓰지 않음). 글: 작업 id · 단계 · 까닭 원문 · 마지막 기록 몇 줄(`events` · 그 일의 로그 끝 20줄) · 남아 있는 것(원고 · 장면표 · 영상 이름). **사진 · 영상은 넣지 않는다.** 까닭 · 기록 줄 · 남은 것 이름까지 **모든 글이 R1.4 거르기(별명)를 지난 뒤에만** 파일에 들어감(작업 제목도 글 안에서는 거른 것).
- 건의(묶음 1 · 1-1)도 같은 길로 — 지금 사람이 하던 push를 서버가.
- push (1.1판 — PLN 대조): 맥 사본은 맥 길대로 **기능 가지를 checkout해 두는 일이 있어** `HEAD:main`은 그 가지의 커밋까지 main에 올린다(결정 32를 넘음). 그래서 **맥 사본과 따로 둔 자리에서 `origin/main` 위에 그 글 하나만 얹은 커밋**을 만든다:
  1. `git fetch origin main`
  2. 맥 사본의 작업 트리 · index를 건드리지 않는 따로 둔 index(`GIT_INDEX_FILE=<데이터 폴더>/_webapp/push.index`)에 `git read-tree origin/main` → `git update-index --add --cacheinfo 100644,<git hash-object -w 글>,suggestions/dev/<파일>` → `git write-tree` → `git commit-tree <tree> -p origin/main -m "suggestions: <파일>"`
  3. `git push origin <새 커밋>:refs/heads/main` — 앞으로 감기가 아니어서 거절되면 1부터 다시(3번까지). 그래도 안 되면 pending.
  - 이 길은 맥 사본의 가지 · HEAD · 작업 트리를 바꾸지 않는다. **main에 들어가는 커밋은 늘 부모가 `origin/main`이고 바꾼 경로는 `suggestions/` 아래 글 하나.** push가 안 되면 `data/working/_webapp/push_pending/`에 남기고 틱마다 다시 — 미첼 화면은 "개발자에게 알렸어요" 그대로(남은 것은 개발자 명령 `jobs.py pending`).
- 제품 저장소 규칙 글(맨 위 `CLAUDE.md` · `AGENTS.md`의 가지 · 검토 줄)에 **예외 한 줄**: "`suggestions/` 아래 글 파일만 검토 없이 main에 바로 push(웹앱 서버가 씀 — 결정 32). 다른 경로 · 그림 · 영상은 안 됨." — 이 건에서.
- [맥에서 확인] 맥 사본의 쓰기 권한 · 가지 — 1차 끝 맥 준비 목록(`MAC_RUN_PHASE1.md` 맥 0에 한 줄 더함).
