## 4. 쉬운 말 진행 기록 · 시각 (R4.1 · R4.2 · R4.3)

- `status.json`에 `events: [{at, step, kind, text}]`를 더한다 — 새 것이 끝. `kind` ∈ `start`(그 단계를 시작) · `check`(확인을 기다림) · `answer`(운영자가 답함) · `done` · `wait`(사용량 등으로 기다림) · `stop`(막힘). `text`는 쉬운 말 한 줄(예: "원고를 다 썼어요 — 확인해 주세요", "원고를 확인해 주셨어요"). 손님 이름 · 연락처는 넣지 않는다(작업 제목도 넣지 않음).
- 쓰는 곳은 **한 함수** `jobs.log_event(job, step, kind)` — 글은 `(step, kind)` 표에서 고른다(AI가 글을 짓지 않음). 부르는 곳: 단계 상태를 바꾸는 `set`(jobs.py) · runner가 일을 시작할 때 · 운영자 답을 받는 서버 처리. 같은 `(step, kind)`가 잇달아 오면 한 번만.
- 시각(R4.2): 단계마다 `started_at`(running이 될 때)을 더한다. 운영자를 기다린 구간은 `events`의 `check` → `answer` 짝으로 읽는다 — 따로 `waits[]`를 두지 않는다(같은 것을 두 번 적지 않게). 보낸 시각 = `created`, 완성본이 생긴 시각 = 마지막 뽑기 단계의 `done` 사건.
- 자세한 기록(R4.3 [안 — 미13 권고])은 지금처럼 `runs[]` · `runs/*.log` · 차례표에 — 운영자 화면에는 안 보인다.
- 옛 작업(`events` 없음)은 빈 기록 + "이 작업은 기록이 없어요" 한 줄.

## 5. '지금' 한 줄 (R4.1)

- `jobs.now_line(job) → {text, sub, todo}`를 서버가 만들어 `/api/job` · `/api/jobs`에 넣는다. 차례:
  1. 막힌 단계가 있음 → "문제가 생겼어요" · sub = 막힘 흐름(ARCH-008, 운영자 먼저)의 한 줄 · `todo` = 운영자가 할 것이 있으면 참.
  2. `check`인 단계 → "<단계> 확인해 주세요" · `todo` 참.
  3. 사용량으로 기다림 → `waiting_words` 그대로 · sub "하실 일 없어요".
  4. running인 단계 → 그 단계의 '하는 일' 진행형(예: "원고를 쓰는 중이에요") · sub "하실 일 없어요 · 다 되면 알려 드려요"(알림은 4-b 전에는 "다 되면 여기에 나와요").
  5. 다 됨 → "다 됐어요".
- 작업 화면: 맨 위 '지금' 띠 → `todo`면 그 확인 카드가 띠 바로 아래 → 단계 카드들 → 진행 기록(새 것이 위, "오후 2:14 …"). 시안은 기록을 단계 위에 두었으나 [안] — 1판은 초안 화4대로 아래.
- 작업 화면에 **템플릿 이름 · 판**을 늘 보인다: "템플릿 시술 사례 세로 릴스 · 1판"(`TEMPLATE.json` `name` + `rev`의 숫자). (R8.4 · R8.2)
- 작업 목록(화3): 세 칸 — **보실 것**(`todo` 참) · **저절로 가는 중** · **끝난 것**(접어 둠). 카드 = 제목 · 시각 · 점(단계 수만큼) · '지금' 한 줄. 아래 탭 '작업' 배지 = 보실 것의 수.

## 6. 화면이 스스로 바뀜 — 바뀜 신호 (R4.1, '20초마다 다시 읽기 대신')

- 서버에 `/api/changes` — **Server-Sent Events**(`text/event-stream`). 서버는 작업 폴더들의 `status.json` 수정 시각을 2초마다 보고, 바뀐 작업이 있으면 `event: job` `data: {"id": …, "sig": …}` 한 줄을 보낸다. 15초마다 빈 줄(`: ping`)로 연결을 살린다. 서버가 이미 `ThreadingHTTPServer`라 연결 하나가 다른 요청을 막지 않는다. PIN 쿠키를 다른 `/api/*`와 같이 본다.
- 화면: `EventSource('/api/changes')`. 신호가 오면 그 작업 화면을 보고 있으면 `/api/job`, 목록을 보고 있으면 `/api/jobs`를 다시 읽는다(지금의 `jobSig` 비교는 그대로). 화면이 가려지면 닫고, 다시 보이면 연다(visibilitychange).
- **끊기면**: 화면은 30초마다 다시 읽기로 돌아가고 다시 연결을 시도한다. 아이폰 사파리가 뒤로 간 탭의 연결을 끊는 것은 정상 — 4-b 푸시가 그 몫.
- 왜 SSE: 휴대폰 사파리가 기본으로 받고, 서버 쪽은 표준 라이브러리로 되며, https가 없어도 된다. 웹소켓은 서버에 새 라이브러리가 들고, 짧은 주기 읽기는 '대신'이 아님.
- 연결 수가 많아질 일은 없다(운영자 휴대폰 한두 대) — 그래도 동시 연결은 8개까지, 넘으면 503.

## 7. 템플릿 고르는 칸 (R8.4, 결정 17)

- 서버: `templates/*/TEMPLATE.json` 가운데 `kind == "main"`인 것만 센다(`list_templates()`). `/api/templates` → `[{id, name, current}]`.
- 보내기 화면: 둘 이상이면 고르는 칸이 나타나고(기본은 `DEFAULT_TEMPLATE`), 하나면 칸이 없다. 고른 id는 보낼 때 함께 가고, 서버는 `current_template(id)`로 박는다(모르는 id는 400).
- 1차는 `reel-main` 하나 → 칸이 안 보임. 시험은 임시 폴더에 템플릿 둘을 두고 칸이 나오는지 본다.

## 9. 받아들임 기준 (ARCH-009에 옮길 것)

1. 화면(app.html)에 단계 이름표 사본이 없다 — `steps_meta`로만 그린다. 숫자 칸으로 단계를 가리키는 곳이 0(grep).
2. ARCH-008이 든 바탕에서 작업 화면 단계 카드 수 = 서버 `STEPS` 수, 차례 = `ORDER`. 옛 8단계 작업도 열린다.
3. 상태가 바뀔 때마다 `events`에 한 줄 — 시험: 가짜 claude로 접수 → 원고 → 확인 → 답까지 돌려 `kind` 차례와 `text`(표의 글)를 본다. `started_at`이 찍힌다. 확인을 기다린 구간(check → answer)을 읽는 함수가 맞는 초를 낸다.
4. `now_line`이 5번 차례 1–5대로 — 상태 다섯 꼴마다 시험.
5. `/api/changes`: 시험 서버에서 연결 → `status.json`을 바꿈 → 5초 안에 `event: job`이 옴. PIN 없이는 401. 9번째 연결은 503.
6. 화면 글에 영어 이름표가 남지 않는다 — `test_words`에 탭 · 머리글 · 단계 이름표 검사를 더함(낱말은 한알께서 정하신 것, 허용 목록에 넣지 않음).
7. 템플릿 `kind: main`이 하나면 보내기 화면에 고르는 칸이 없고, 둘이면 나타나며 고른 id가 `status.json` `template.id`에 박힌다. 작업 화면에 "템플릿 <이름> · <n>판".
8. 원고 단추 「이 원고로 갈게요 →」 · 누른 뒤 흐름은 지금과 같다(승인 hash 그대로 — 묶음 3).
9. 시험 전부 — 저장소 전부를 풀어 **환경 값 없이** `python -m unittest discover -s app/webapp/tests` OK. 손님 정보는 시험 자료에도 넣지 않는다.
10. 화면 그림: 작업 화면(진행 중 · 확인해 주세요 · 다 됨) · 목록(세 칸) — 390px 폭 그림 세 장을 반환서에.
