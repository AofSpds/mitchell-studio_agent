## 2. 작업자를 부르는 길 — `app/webapp/worker.py` (요청 3번 1)

### 2-1 한 일 = 한 대화 = 카드 한 장 (나-6을 고침)

- 일꾼(`mac_gui`)이 일을 잡으면 → 서버가 그 일의 카드 글을 만들고 → 작업자를 **새로** 띄워 그 카드만 하게 함 → 작업자가 결과 줄을 쓰고 끝냄 → 서버가 지금처럼 파일로 확인 → 다음 칸이면 서버가 **다음 일을 차례표에 넣음**.
- 그래서 "다음 카드 해 줘"가 필요 없다. 한 대화가 '멈춤'을 써도 그 대화만 끝난다 — 다른 작업은 다음 일로 간다(R5.3).
- `mac_gui` 길은 한 번에 하나(맥 화면은 하나). 들어온 차례대로, 기다리는 일(사용량 · CapCut 켜짐)은 건너뛰되 차례는 지킨다(묶음 2의 `edit`와 같은 꼴).

### 2-2 띄우는 명령 — 설정 한 곳에서

- `worker_model.py`의 enum 값마다 **명령줄 이름**을 더한다: `Model.GPT_6_2_SOL` → `cli: "<맥에서 확인한 이름>"`, `Effort.HIGH` → `cli: "<맥에서 확인한 값>"`. **값을 지어내지 않는다** — 맥에서 `codex --help` · `codex exec --help`와 OpenAI 공식 문서(developers.openai.com/codex)로 확인한 것만 넣고, 확인 전에는 비워 두면 일꾼이 "맥의 도우미가 준비되어 있지 않아요"로 멈춘다.
- 명령 꼴(맥에서 확인해 고침): `codex exec -m <모델 cli> -c model_reasoning_effort=<세기 cli> <권한 플래그> -` + 표준 입력으로 카드 글, cwd = 저장소 맨 위, timeout(⑥ 카드 10분 · 얼굴 15분 — `WEBAPP_WORKER_TIMEOUT`).
- 실행 파일: `WEBAPP_CODEX_BIN` → `shutil.which("codex")`(PATH에 homebrew 붙인 뒤 — 묶음 2와 같음). `--help`에 없는 플래그는 빼고 `runs`에 적는다(묶음 2 `claude`와 같은 방식).
- **권한 플래그**: 지금 맥 Codex 앱에서 쓰는 권한 A(「전체 권한 + 승인 안 물음」 — 운영자가 앱에서 켠 것)와 **같은 넓이를 넘지 않게**. 명령줄에서 그 넓이에 해당하는 플래그가 무엇인지는 맥에서 확인 — 이것이 새 허락이 되면(기7) 5번 승인 한 장에 함께 여쭘.
- **명령줄에서 화면 조작이 되는지가 이 묶음의 첫 갈림** — 1차 끝 맥 시험의 첫 줄(9번 맥 0). 안 되면 이 길(2-2)만 바꿔 끼운다: 작업자 부르기를 `worker.py` 한 곳에 모아 두었으므로, 카드 · 결과 줄 · 확인 · 오류 흐름은 그대로 쓴다. 바꿔 낄 후보는 그때 RSCH 조사로(ARCH가 지어 정하지 않음).

### 2-3 확인 (지금 그대로 + 더함)

## 3. AI 얼굴 — Face 단계 (묶음 3-2)

### 3-1 단계

- 단계를 9개로: Send · Intake · Script · **Face** · Edit · Preview · Voice · Done · Post (옛 기획 그대로). `status.json`의 옛 작업(8단계)은 읽을 때 Face를 `done`(해당 없음)으로 채워 끊기지 않게 — 저장된 값이라 옛 값도 읽히게(ARCH-002에서 배운 것).
- 원고 「좋아요」 → `intake.json`의 `ai_face`가 `have: true`면 Face `done`(올린 사진 씀) → `edit` / `plan: "make"`면 Face `now` → `face` 일.

### 3-2 만드는 길

- 서버가 준비: 시술 후 사진 중 하나를 `data/working/<작업>/for_chatgpt/after.jpg`로 **복사**(원본 `data/incoming`은 작업자에게 보이지 않게 — 옛 기획). 고르는 것은 `intake.json`의 `after` 중 첫 장 [안], 회차 비교면 `prev_face.png`도.
- 카드(작업자): 맥 ChatGPT 앱 새 대화 → `after.jpg` 첨부 → 정한 글(머리 색 · 형태 · 길이 · 결은 그대로, 얼굴만 `facts.model_age` 여성 모델, 9:16, 글자 · 로고 · 워터마크 없음, 회차면 같은 사람) → 만든 것을 스스로 견줘 다르면 다시(최대 2번) → **그림을 `for_chatgpt/face_<N>.png`로 저장** → 결과 줄 `얼굴: 저장함 · 모델: …` / `얼굴: 머리 다름 · …` / `얼굴: 못 만듦 · 이유: …`.
- **저장 길**: 앱의 저장 창에서 곧바로 `for_chatgpt/`를 골라 저장 — 서버도 작업자도 `~/Downloads`를 읽지 않게(새 허락 창을 피함, 옛 기획 :45). 이 길이 되는지는 1차 끝 맥 시험에서 봄(옛 기획에서도 시험 안 됨). 안 되면 R32.4(직접 올리기)로 일이 멈추지 않게 하고, 다른 길은 그때.
- 서버 확인: `face_<N>.png`가 이번 실행 뒤 생김 · 세로가 긴 9:16(±2%) · 그림 파일. 아니면 2-5.

### 3-3 확인 화면 (화5-2 · R32.3 — 기본 켬, 결정 06)

- 왼쪽 시술 후 사진 · 오른쪽 만든 얼굴, 아래 "머리 색과 모양이 같은지 봐 주세요."
- 단추: **「이 사진으로 갈게요 →」** · 옆에 늘 **「다시 만들기」**(남은 횟수 보임 — 운영자 다시 만들기 3번 [안], 넘으면 「개발자에게 넘기기」) · 「가진 사진 올리기」(R32.4).
- 결과 줄이 '머리 다름'이면 노랑 띠 "머리가 조금 달라 보여요" — 그래도 「이 사진으로 갈게요 →」는 누를 수 있음(가장 가까운 것으로).
- 잠긴 줄 "얼굴 : AI 합성 표시는 영상에 항상 들어가요 🔒".
- 「이 사진으로 갈게요 →」 → `face: {file, n, approved_at, hair_diff}` 기록 · Face `done` → `edit` 일. 「다시 만들기」 → `face` 일(N+1, 앞 판은 지우지 않음).
- 「가진 사진 올리기」 → 그 작업 batch에 더하고(묶음 3의 「더 보내기」 길) `ai_face.have: true` → 이 화면으로 돌아와 같은 확인.
- 옵션 「얼굴 확인」은 만들지 않는다 — 늘 켬(결정 06이 '기본 켬'이지만 끌 길을 둘지는 말씀이 없어 두지 않음. 필요하면 그때).
