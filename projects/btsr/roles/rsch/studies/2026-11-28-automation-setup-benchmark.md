**먼저 비교할 셋: MakeMyClip → FableCut → FrameWright.** 같은 편집 상태를 이어 쓰는 근거가 뚜렷한 순서로 고른 시험 후보이며 성능 순위·도입 확정이 아니다.
FableCut은 사진·영상·자막·판 충돌, FrameWright는 변경 검토·승인·올릴 글을 비교하는 기준이 된다. 둘의 라이선스와 FrameWright의 우리 환경 호환은 실행 준비 전에 확인할 빈칸이다.
그 조건이 맞지 않으면 OpenFilm을 다음 후보로 검토한다. OpenCut classic과 HyperFrames는 각각 기존 시간선과 Studio 조립 방식의 예비 비교 대상으로 남긴다.
먼저 고칠 기기, 조직 안 사용/외부 배포, 꼭 필요한 편집 기능은 S38 7절의 미정 사항이다. 현재 순서는 컴퓨터에서 하는 첫 비교에 한정하며 휴대폰 적합성을 결론 내리지 않는다.

## 4. 첫 판에 넣지 않을 것

- 합성 목소리·배경 음악·효과음 만들기: X X-01·CN C4·JP JP03·KR K06 등의 전체 흐름을 그대로 옮기지 않는다.
- 생성 사진·생성 영상·3D 장면, 사진 손질본: CN C3·X X-02·KR K08의 제작 기능은 직접 촬영 자료 편집과 별도다.
- 자동·예약 게시, 계정 연결: R C05·CN C4·JP JP07·KR K06은 흐름 참고만 한다. 영상·한글 자막·올릴 글을 확인하고 받는 데 맞춘다.
- 외부 편집기로 마지막에 다시 옮겨 고치기를 기본 흐름으로 삼기: JP JP06·KR K04·K08은 참고하되, 첫 판은 우리 앱 안 편집 화면을 목표로 한다.

## 5. 기술 시험 후보 갱신 — T01 다음 차례

전부 **읽은 이의 판단으로 제안한 시험**이며 이 창에서는 준비 파일 생성·설치·실행하지 않았다. 아래 표가 설치 허락을 받은 기록은 아니다.
기준 [원점 연구 한 장](2026-11-28-origin-research-one-sheet.md) 13–44줄의 미확인 사항을 유지한다. 의뢰서에서 길과 결과는 이미 골랐으므로 다시 묻는 단계로 돌리지 않는다.

| 차례 | 할 시험·남길 결과 | 통과를 가릴 기준 | 설치 허락·선행 조건 |
|---|---|---|---|
| 먼저: 후보 조건 확인 | 우선 셋의 정확한 판·라이선스·의존 부품·운영체제·저장 형식을 확인하고 비교표 빈칸 채우기 | 실행·수정·배포 범위를 구분하고 미확인 항목을 해소 | 문서 읽기 자체는 설치 없음. 웹 재확인은 후속 조사 범위; 이 창은 하지 않음 |
| 다음: 편집표 왕복 | 같은 사진 2장·영상 2개, 한글 자막·올릴 글로 초안 만들기. 화면에서 순서·컷·사진 길이·구도·자막을 고쳐 저장→닫기→다시 열기→자동 부분 수정 | 사람이 고친 값·잠금이 남음. 낡은 판 수정 거부·묶음 되돌리기. 변환 중 잃는 칸 기록 | **실제 앱·실행 도구·한글 글꼴 준비 허락 필요.** 설치 목록을 구체화해 RSCH가 진행. 개인 정보 없는 시험 소재 사용 |
| 이어서: 실제 출력과 전달 | 같은 판의 작은 초안→최종 세로 영상·자막·글 묶음. 장면 경계와 전체 재생 확인 | 사진 길이·영상 구간·세로 배치·한글 글꼴/줄바꿈/잘림/시각 일치. 승인 판과 전달물 일치 | 앞 시험에서 허락받아 준비한 범위. 새 도구·글꼴이 필요하면 준비 범위 추가 확인 |
| 이어서: 사람 수정 뒤 중단·재개 | 승인 후 표 변경, 굽기 중 중단, 완료 뒤 재요청, 옛 시도의 늦은 응답을 실제 출력과 연결해 확인 | 옛 승인은 무효, 완료 결과 재사용, 늦은 응답이 새 결과를 덮지 않음. 시간·재시도·사람 수정 횟수 기록 | 준비한 로컬 범위에서 비교. 실제 유료 호출은 공급자의 중복 요청 방지·결과 조회를 별도 시험해야 함 |

사진·영상의 수는 비교용 예시이며 제품 입력 제한이 아니다. 한 번 성공으로 끝내지 않고 같은 입력을 다시 만들어 빠지는 칸·사람 수정량·전체 시간을 후보별로 비교한다.
공통 편당 비용은 아직 모른다. 준비·분석·굽기·재시도·사람 검토 시간을 나누어 남기고, 실제 외부 호출을 하지 않은 시험으로 재결제 방지를 보장하지 않는다.

## 6. 한계와 남은 것

- 다섯 글의 41개 카드는 제작자·사용자·판매자 기록이며 독립 재현 41건이 아니다. 시간·값·성공 수치를 서로 다른 조건에서 가져와 순위나 공통 단가로 묶지 않았다.
- 이 창은 지정된 로컬 글만 읽었다. 웹·영상·프로그램을 열어 동작 확인하지 않았고 내려받기·설치·외부 호출·커밋·push를 하지 않았다. 로컬 권한 거부는 없었다.
- [의뢰서의 RSCH 수용](../sub/s39_benchmark_setups/OPEN_PACKET.md)은 FableCut·fastCutVid·Sashimono Edit·FrameWright·dsh-autocut·GPTers K03의 일부 원문 대조를 기록한다. 이 창의 재확인이나 실행 시험이 아니다.
- 직접 촬영 사진·영상 혼합 → 공통 편집표 → 우리 앱에 내장한 편집기 → 한글 자막·올릴 글을 한 번에 끝까지 입증한 사례는 없다. 한국어 글의 사례도 한글 자막 품질 실측 근거는 아니다.
- X 직접 본문·Tangled와 知乎는 원조사에서 접근 거부. 브런치는 멤버십 벽, JP JP08은 유료 경계까지만 읽었다. 다른 조회 오류·미확보 파일은 각 원조사 4절에 구분돼 있으며 이 창에서 다시 열거나 우회하지 않았다.
- **여섯 달 넘은 카드:** CN C8(2026-04-08), KR K06(2026-04-07), K07(2025-12-24·변경 2026-03-09), K08(2025-09-17). 흐름 참고로만 사용. S38의 OpenCut classic도 마지막 기록이 2026-05-18이며 보관 상태다.
- 날짜 없는 저장소와 상대 날짜만 있는 글은 최신이라고 확정하지 않았다. 소개 글 당시 기능과 현재 README 기능을 구분한 원카드의 제한도 유지한다.
- OpenFilm 소개 영상의 대화는 대본 시연이고, Sashimono의 화면 예시 채팅도 촬영용이다. 독립적인 자동 편집 성능 근거로 쓰지 않는다.
- 아직 못 한 핵심: 라이선스 빈칸 해소, 후보 셋 실제 왕복·한글 출력·휴대폰 조작·우리 앱 내장, 같은 조건의 시간·비용 비교. 이 문서는 다음 비교 시험의 근거와 제안까지다.
