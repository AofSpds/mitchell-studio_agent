# 가정 및 결과 — 디지털펌 한 편

가짜 작업 번호는 `2026-11-21_1530`이다. 소재 이름·작업 번호와 아래 판 길이·목소리·음악은 가정이다. 가짜 Request는 [request.txt](request.txt)에 있다. 사진·영상·CapCut 프로젝트는 경로와 결과만 적었다.

1. `data/incoming/2026-11-21_1530/`에 뒷모습 사진 두 장, 시술 전 사진 한 장, 시술 과정 세로 12초 영상과 Request를 받았다고 치고 [접수 표](intake.md)와 [읽는 표](intake.json)를 썼다. 코드 기본값은 영상 14초, 음성 1.5배, 자동으로 고르는 음성·음악, 끝 문구 켬, 게시 대상 5곳이다. 실제 설치의 기본값 파일은 확인 범위 밖이다. 시술 과정 영상은 접수 지시대로 쓰지 않는 소재에 두었다.
2. [원고](script.md)와 상태 명령 `python3 app/webapp/jobs.py set 2026-11-21_1530 script check`가 코드가 기다리는 결과다. 원고가 멈추는 것이 실제 경로의 첫 지점이다. 이후는 미첼이 시안에 없는 「좋아요」를 눌렀다고 가정한다. 원고에는 접수 사실 셋에 담은 내용만 쓰고, 썸네일 후보 줄은 ⑥의 읽기 자막에서 뺀다.
3. 명령줄 설정과 점검도 통과했다고 가정한다. `data/working/2026-11-21_1530/for_chatgpt/after.jpg`는 `after-01.jpg`의 사본이다. 맥 작업자가 새 대화에 이 사본 한 장만 첨부하고, 머리를 두고 얼굴만 50대 모델로 바꾸라는 카드를 보낸다. 머리 색과 모양을 견준 뒤 세로 900×1600의 새 `for_chatgpt/face_1.png`을 저장했다고 가정한다. [얼굴 결과](face_result.txt)의 줄과 이미지가 함께 있어야 `Face=check`가 된다. 미첼의 확인 뒤 같은 사진을 첫 컷으로 쓴다.
4. [v1 장면표](scenes.json)의 시간은 초다. 진행 중 영상의 실제 재생과 크롭은 확인할 수 없으므로, 장면표의 입력·표시·시간과 승인 글을 대조했다. 처음 0–2초는 합성 표시, 5–7초는 시술 전 표시다. 9–12초와 12–14초는 `repeat_of`의 0부터 세는 번호로 시술 후 장면을 다시 사용한다. 편집의 확인 명령과 저장 명령이 성공했다고 가정한다. 빌더는 끝에 `edit=done`을 쓰고 `2026-11-21_1530_v1` 프로젝트를 남긴다. Preview는 `later`다.
5. Voice·Music·Export는 매번 새 대화에서 해당 프로젝트만 연다. 음성을 자막당 한 번, 곡은 한 트랙만 넣는다. CapCut을 닫고 해당 줄을 차례대로 `chatgpt_result.txt` 끝에 더한다. [v1 결과](chatgpt_result.txt)의 세 줄이 그 기록이다. Fit은 서버가 별도로 실행한다. `voice_fit_done` 내용 예(수치는 가정).

   ```text
   간격 맞추기 끝 · 겹침 0.2초 → 0초 · 영상 14초 → 14초 · 마지막 목소리 끝 11.5초
   ```

   가정한 완성 파일은 `data/output/2026-11-21_1530_v1.mp4`다. 첫째·둘째 줄은 프로젝트 검사 전에는 `check`이며 셋째 줄은 저장 파일을 대신하지 못한다. 새 파일이 15초간 안정된 뒤 검사를 통과하면 Done의 확인으로 간다. 코드와 가짜 Codex의 성공 줄은 같은 문법이다.
6. 미첼이 v1을 보고 [수정 요청](done_수정_요청.txt)을 보낸다. `feedback/done_<날짜>_<시각>.txt`로 저장된다. 현재 앱은 Edit 예약을 하지 않는다. 가정으로 작업자가 v1의 **CapCut 프로젝트를 복제**해 `2026-11-21_1530_v2`를 열고 읽기 자막만 키운다. v1과 비교해 시술 전·AI 표시를 유지한다. 마지막 12–14초만 자른다. [v2 장면표](v2/scenes.json)는 그 12초 컷을 보여 준다. 글자 크기는 빌더가 장면표에서 읽는 항목이 없으므로 CapCut 복제본에서 키웠다는 가정이다.
7. v2는 원고가 같고 복제본에 Voice·Music이 남아 있으므로, 기존 분기에서 Edit 완료 뒤 Fit → Export로 갈 수 있다(`jobs.py:1239–1254,1777–1826`). 음성은 12초 전에 끝나고 음악은 12초에서 끊기게 한다. Fit 뒤 실제 최종 길이가 v1보다 정확히 2초 짧은지 검사하는 것은 따로 필요하다. [v2 결과](v2/chatgpt_result.txt)는 기존 작업 결과 파일의 세 줄 뒤에 새 Export 줄만 덧붙인 형태다. 서버는 이미 읽은 줄 수를 알고 새 Export 줄만 반영한다. 새 내보내기 이름은 `data/output/2026-11-21_1530_v2.mp4`다.
8. 승인한 판 v2로 [Post 캡션](post/)을 냈다. 가정으로 uploader 지침을 적용했다. 별도 게시 메모가 있다면 Instagram의 AI 정보, YouTube의 합성 콘텐츠, TikTok의 AI 생성 콘텐츠 표시를 안내한다. 시안의 Post에서는 미첼이 캡션을 복사하고 게시한 곳만 「올림」으로 표시한다. 현재 코드의 Instagram 안내는 15~30초로 적혀 있어 12초 가정과 다르다. 코드의 Done 규격 검사에는 길이 항목이 없다(`reel_api.py:25`, `jobs.py:516–534`). 실제 플랫폼 게시 가능 여부는 이 시험에서 판정하지 않았다.
