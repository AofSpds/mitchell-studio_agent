# 영상 제작 시뮬레이션 — 바른 길

- 현재 코드는 접수 뒤 원고를 쓰고 「좋아요」를 기다린다. 시안에는 그 확인 화면이 없어 그대로면 Face에 닿지 못한다.
- 원고 확인을 대신했다고 가정해도, 현재 제품 판의 맥 작업자 명령줄 설정이 비어 있어 Face에서 개발자에게 넘어간다. 이 설정까지 가정하면 v1의 파일·결과 줄을 대조하고 Done까지 걸어 볼 수 있다.
- 완성본 수정은 글만 저장돼 v2 작업이 시작되지 않는다. v2로 내보낼 때 v1을 보존할 파일 규칙은 있다. Post는 승인 영상과 이미 써 둔 캡션을 읽지만 캡션을 만드는 작업은 예약하지 않는다.

근거 판은 제품 로컬 `origin/main` `3072e7e`, 웹앱 시안 3판과 [요청서 14–16번](../../requests/BTSR-RSCH-003_webapp-phase1-capcut/요청.md)이다. 아래 제품 경로에서 `app/webapp/`은 생략했다. 실제 실행 대신 고정된 코드와 [가짜 결과](out/가정_및_결과.md)를 대조했다. [받은 지시 원문 발췌](out/받은_지시.md)에 지시와 줄을 묶었다.

## 진짜 맥에서만 알 수 있는 것

- GPT-6.2 Sol High 명령줄 설정과 새 대화에서 화면 조작이 되는지, 시작 전 점검과 권한 상태, 카드당 20회·3분 안에 끝나는지.
- 뒷모습을 기준으로 머리 색·모양·길이·결이 유지되는지, PNG가 제자리에 저장되는지, AI 표시와 시술 전 표시가 잘 보이는지.
- CapCut 바탕 프로젝트와 자막 스타일, 글자 확대 후 화면 잘림, 1.5배 목소리 발음·음악 균형, 2초 절단 뒤 음성·자막·음악 끝과 Fit의 길이 변화.
- 두 MP4의 실제 저장·규격·소리·판 보존과 아이폰에서의 재생·저장·Post 전환. 본문은 소스 대조와 가짜 결과 범위로 확인했다.
