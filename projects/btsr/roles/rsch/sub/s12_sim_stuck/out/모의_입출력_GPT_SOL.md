# 모의 입력과 결과

가짜 작업 번호 A는 `2099-04-01_1200`, A를 처음부터 시작한 시도 A′는 `2099-04-01_1200-2`. 이 번호와 아래 한도 예시 시각은 시험값. 현재 코드가 같은 업로드로 A′를 만든다는 뜻은 아니다.

## Send · Intake

- `data/incoming/2099-04-01_1200/`: `after_15s.mp4`(세로 15초), `after_clear.jpg`(선명한 시술 후), `after_blur.jpg`(흐린 시술 후), `before.jpg`(시술 전). `request.txt` 내용은 「애쉬 브라운 염색」. Options는 공장 기본값 가정(길이 14초, 목소리 1.5배, 목소리·음악 자동, 끝 문구 켬). 영상의 시술 후 자세와 사진의 색·모양은 모의 입력 가정.
- `intake.json`은 Claude 첫 출력, `intake.md`는 사람이 읽는 표. 현재 서버는 `m:after_blur.jpg` → `f:change` → `f:model_age` 순으로 질문을 만든다. 가짜 답은 각각 「쓰지 않음」, 「염색 후 머리색」(직접 적음), 「30대」. 첫 답 뒤 흐린 사진은 `kind: other, sure: true`가 되고 `why`가 지워진다. 뒤의 두 값은 `from: answer, sure: true`. 새 화면에서는 그 첫 답에 대응하는 단추를 「이 사진 빼고 만들기」로 시험했다.
- 「사진 다시 올리기」 가정: 기존 사진은 보관하고 해당 사진만 제외, 새 사진 한 장을 같은 묶음에 더하고 접수 다시. 「모르겠어요 — 개발자에게 알리기」 가정: 사진 문제 한 줄을 남기고 화면 9로, 원고 일을 넣지 않는다. 둘 다 현재 흐림 질문의 답으로 처리할 길은 못 찾았다.
- Claude의 접수·원고 정상 출력 예시(각각 종료 0, `fake_claude.py:53–55`). 실제 통과는 표 또는 원고와 상태를 본다.

```json
{"type":"result","subtype":"success","is_error":false,"num_turns":3,"duration_ms":1200}
```

## Script · Face · Edit

- `script.md`의 문장 일곱 줄을 쓰고 `python3 app/webapp/jobs.py set 2099-04-01_1200 script check` 했다고 가정. A′에서도 같은 답을 다시 받은 모의 경로에서는 작업 번호만 A′로 바뀐다.
- Face 카드에서 선명한 사진의 복사본 `for_chatgpt/after.jpg` 한 장을 열고, 카드의 30대 모델 문구를 그대로 보낸다고 가정. 머리 확인 → 직접 `for_chatgpt/face_1.png`로 저장 → 결과 파일에 한 줄 → 미첼 확인. 아래의 이미지는 이름과 900×1600 규격만 가정했다.

```text
얼굴: 저장함 · 모델: GPT-6.2 Sol
```

- Edit는 `scenes.json`으로 14초를 잡고 건너뜀 없이 이어 붙임. 반복은 첫 AI 얼굴과 뒤 영상의 일부이며 AI 표시가 따라간다. A에서 한 번 실제 장면 붙이기에 실패하는 별도 갈래의 상태 명령(Claude가 쓰라는 꼴, 현재 runner가 마지막 실패 때 이유를 덮는지 확인):

```text
python3 app/webapp/jobs.py set 2099-04-01_1200 edit stop --reason "장면을 이어 붙이지 못했어요"
```

## ⑥ Voice에서 멈춘 A

장면을 만드는 카드는 Edit에 있다. 이 갈래에선 Edit가 끝났다고 처리된 초안이 Voice에서 열리지만 화면에서 쓸 장면·자막이 보이지 않는다고 가정. Voice는 편집을 다시 맡지 않으며 공통 멈춤 규칙으로 빠진다. 적힌 전체 이름의 초안만 열기 → 자막과 타임라인 확인 → 같은 방법 3번과 다른 방법 1번 가정 → 종료 확인 → `chatgpt_result.txt`에 첫 줄. 웹앱이 까닭을 붙여 새 카드로 한 번 더 부른 뒤 둘째 줄을 더한다.

```text
멈춤 · CapCut 타임라인 · 지정한 초안을 열었지만 장면이 비어 있어 이어 붙일 수 없었어요
멈춤 · CapCut 타임라인 · 지정한 초안을 다시 열고 타임라인을 확인했지만 장면을 읽을 수 없었어요
```

제품의 Stop 정규식은 이 두 줄과 `fake_codex.py:98–100`의 열쇠형 `멈춤 · 이유: … · 모델: GPT-6.2 Sol`을 둘 다 받는다. 공통 카드가 시킨 위 두 줄에는 모델 열쇠가 없으며, 모델 확인에는 별도로 실제 Codex 기록이 필요하다.

## A′의 한도 · 이어서 완성

화면 9에서 A′를 만드는 것은 고침을 가정했다. 이 갈래의 작업자 한도는 Voice 결과 파일에 다음 줄을 더한 경우(종료 0, 표준 출력에 해제 시각 없음). 가짜 시각 16:00 KST에 이 줄을 받았다고 두면 다음 날 07:00 KST 대기가 된다.

```text
멈춤 · 사용량
```

Claude 갈래는 A′의 Edit에서 한도. 정상 성공 줄 대신 아래처럼 내고 종료 1. 아래는 `fake_claude.py:111–113` 리터럴이며 날짜는 과거라서 실제 대기 계산에서는 다음 07:00 KST로 돌아간다. 미래의 10자리 Unix 초를 내면 그 시각이 쓰인다.

```text
Claude AI usage limit reached|1700000000
```

두 대기 해제 뒤에는 저장된 조각을 먼저 읽는 Voice/Music 카드로 이어 간다고 가정. 같은 결과 파일에 다음 줄을 순서대로 추가. 아래 곡·목소리 이름은 가짜이며, Fit 로그는 작업자가 쓰는 결과 줄이 아니라 서버가 프로젝트를 검사한 뒤 쓰는 한 줄 형태다.

```text
목소리 끝 · 목소리: 시험 목소리 · 모델: GPT-6.2 Sol
음악 끝 · 음악: 시험 곡 · 모델: GPT-6.2 Sol
다 했어요 · 파일: 2099-04-01_1200-2_v1.mp4 · 모델: GPT-6.2 Sol
```

```text
간격 맞추기 끝 · 겹침 0초 → 0초 · 영상 14초 → 14초 · 마지막 목소리 끝 13.5초
```

- Export는 설정을 읽기만 하고 해당 파일을 내보낸다고 두었다. 완성에서 승인할 수 있는 파일은 MP4, 1080×1920, 30fps, 소리가 있고 음성 겹침 없음으로 가정했다. 모의 Post 캡션 `instagram.txt`의 제품 내 자리 예시는 `data/upload/instagram/2099-04-01_1200-2.txt`.
- 다른 Send 갈래 B는 새 묶음과 새 작업 번호. A의 개발자 기록은 남기고 미첼의 Jobs에서는 B만 보인다고 가정했다. 현재 코드는 두 작업을 함께 조회할 수 있다.
- 재시동 갈래: Claude 편집 실행 중 꺼짐, 작업자 Voice에서 저장 직전/직후 꺼짐, 한도 대기 중 꺼짐을 각각 상태로 대조했다. 어디서 끊겼는지에 따른 예상은 본문에 있다.
