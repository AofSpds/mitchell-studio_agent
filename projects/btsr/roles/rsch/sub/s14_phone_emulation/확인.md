# 아이폰 크기에서 보내다가 끊기면 어떻게 되나요?

## 안 되는 것

- **보내는 중 새로 고침을 그대로 진행하면 처음부터 다시 해야 합니다(예시 7).** 사진 두 장이 먼저 도착한 뒤 영상을 보내던 중이었습니다. 화면을 떠날지 한 번 물었지만, 돌아온 첫 화면에는 고른 파일도 요청 글도 없었습니다. 이미 받은 사진이 있다는 안내도 없었습니다. [새로 고침 뒤 화면](shots/E07_새로고침.png)
- **로그인이 이미 풀린 화면에서 보내기를 눌렀을 때 번호를 다시 넣을 수 없는 경우가 있었습니다(예시 12).** 시험용 로그인을 끝낸 뒤 열려 있던 화면에서 눌렀습니다. 이 PC의 웹앱에 바로 연결한 시험 한 번에서 번호판 대신 영문 오류 화면(501)이 나왔습니다. 전송 도중에 로그인이 풀렸다는 응답을 받은 시험에서는 번호를 다시 넣고 같은 묶음을 마저 보냈습니다. 실제 아이폰에서 어느 쪽이 나타날지는 남아 있습니다.

## 불편한 것

- **세 번째 파일이 끊겨도 막대가 끝까지 차 보였습니다(예시 11).** 제목과 다시 고르는 단추는 끊겼다고 알려 주지만, 막대만 보면 다 보낸 것처럼 보입니다. [끊겼을 때 화면](shots/E11_다시고르기.png)
- 와이파이가 끊긴 채 처음 보내면 맥북이 켜져 있는지부터 묻습니다. 고른 사진과 글은 남습니다(예시 10). [안내 화면](shots/E10_연결끊김.png)

## 잘 되는 것

- **사진 두 장과 영상 한 개를 다시 모두 골라도, 이미 받은 사진 두 장은 다시 보내지 않았습니다.** 영상만 마저 받아 한 편이 생겼습니다. 이 PC의 웹앱을 전송 중 껐다 켠 경우에도 「다시 보내기」로 이어졌습니다. [다시 고르기](shots/E11_다시고르기.png) · [접수된 한 편](shots/E11_보낸뒤.png)
- 영상 전송이 끊어지지 않은 채 멎었을 때 약 32초 만에 스스로 회복했습니다. 전송을 취소할 때는 한 번 더 묻고 「계속 보내기」로 돌아갈 수 있습니다. [멈추기 전 확인](shots/E08_멈출까요.png)

**시험 조건** 2026년 11월 22일 01:39~01:44 한국 시각에 제품 판(`8b0d084`)을 이 PC에서 열었습니다. 아이폰 14와 같은 크기(390×664)의 브라우저(WebKit)에 손가락 누르기를 보냈습니다. 색종이 그림 두 장과 색종이가 움직이는 시험 영상 약 12메비바이트(12 MiB)를 썼습니다. 전송이 멎는 시간을 줄이지 않았습니다. 파일 이름에 한글·빈칸을 넣었고, 같은 이름의 서로 다른 그림은 둘 다 저장됐습니다. 아이폰 사진 확장자(.heic · .heif)를 붙인 시험 그림도 접수됐습니다. 실제 아이폰 원본 사진을 열거나 변환한 시험은 따로 남습니다.

## 진짜 아이폰에서만 볼 수 있는 것

- 사진 두 장과 큰 영상을 보낼 때 화면을 잠그거나 다른 앱에 잠깐 다녀온 뒤, 몇 번째 파일인지와 다시 보내는 단추가 보이는지.
- 사진 보관함에서 같은 원본을 다시 고를 때 다른 이름·크기 또는 다른 사진 꼴로 건네주는지. 앱은 이름·크기·앞부분을 대조하므로 달라지면 먼저 보낸 사진도 다시 보낼 수 있습니다.
- 큰 영상이 준비되는 동안 사진 고르기 창에 무엇이 보이는지, 아이클라우드 사진을 가져오거나 아이폰 사진(HEIC)을 바꾸는 시간에 다음 동작을 알 수 있는지.
- 매장에서 쓰는 보안 주소(HTTPS)에서 화면 꺼짐 방지, 홈 화면에 추가, 닫힌 앱의 알림, 공유 창에서 사진 앱에 저장, 실제 한글 자판으로 글을 입력할 때의 가림.
