# 아이폰에서 보내기가 끊기면 어떻게 되나요?

## 안 되는 것

- **이름이 다른 사진은 건너뛰지만, 이름이 겹친 사진은 한 번 더 들어갈 수 있습니다.** 사진 두 장과 영상 한 개를 보냈습니다. 영상에서 끊긴 뒤 같은 세 개를 다시 골랐을 때, 이름이 다르면 영상만 마저 보냈습니다. 서로 다른 사진 두 장의 이름이 같으면 두 번째 사진도 다시 보냈습니다. 한 편에 **사진 세 장과 영상 한 개**가 들어갔습니다. [다시 고르는 화면](shots/E11_다시고르기.png) · [돌아온 자료 네 개](shots/E34_이름겹쳐다시고름.png)
- **새로 고침을 그대로 진행하면 고른 파일과 요청 글을 잃습니다.** 사진 두 장이 먼저 도착한 뒤 영상을 보내던 중이었습니다. 화면을 떠날지 한 번 물었지만, 새로 열린 첫 화면에는 보내던 것이 있다는 안내도, 이어 보내는 단추도 없었습니다. [새로 고침 뒤](shots/E07_새로고침.png)
- **로그인이 이미 풀린 상태에서 보내기를 누르자 번호판 대신 영문 오류 화면(501)이 한 번 나왔습니다.** 이 PC의 웹앱에 바로 연결해 시험용 로그인을 끝낸 뒤 누른 결과입니다. 이때는 번호를 넣을 수 없었습니다. 반면 영상 전송 도중 로그인 만료 응답을 돌려준 시험에서는 번호를 다시 넣고 같은 묶음을 마저 보냈습니다. 오류 화면은 당시 화면 글로 확인했고, 사진은 번호를 다시 넣을 수 있었던 경우입니다. [다시 로그인한 뒤](shots/E12_로그인뒤.png)
- **접수 물음에서 「더 보내기」로 보낸 파일이 멎으면, 기다려야 할지 다시 골라야 할지 알 수 없습니다.** 33초를 기다려도 화면에는 원래 물음과 「더 보내기」만 보였습니다. 연결을 완전히 끊자 맥북을 확인하라는 안내가 떴습니다. 같은 물음에서 「더 보내기」를 다시 눌러 사진을 보낼 수 있었습니다. [33초 기다린 뒤](shots/E17_기다린뒤.png) · [끊은 직후](shots/E17_연결끊은뒤.png)

## 불편한 것

- **다 보낸 것처럼 보이는 막대.** 세 번째 파일을 받지 못했는데도 막대는 끝까지 차 있었습니다. 이때는 제목의 「보내다 끊겼어요」와 그 아래 단추로 다음 행동을 알 수 있습니다. 와이파이가 끊긴 상태에서 처음 보내면 맥북이 켜져 있는지부터 확인하라고 합니다. [끊긴 막대](shots/E11_다시고르기.png) · [첫 연결 안내](shots/E10_연결끊김.png)
- **사진을 이미 보냈는데도 잠깐 「먼저 사진 · 영상을 골라 주세요」가 남습니다.** 고른 파일 없이 보내기를 누른 뒤 곧바로 사진을 골라 보내면, 접수됐다는 글과 앞 화면의 안내가 함께 보입니다. 요청 글을 비우고도 접수는 됐습니다. [두 안내가 겹친 화면](shots/E03_요청없이접수.png)
- **사용법의 얼굴 설명이 실제 단추와 다릅니다.** 사용법에는 세 번까지 다시 만들거나 「가진 사진 올리기」를 누르라고 적혀 있습니다. 실제로는 두 번 뒤에 「이 사진으로 갈게요 →」만 남았습니다. 두 번을 다 썼다는 말은 물음표 안에 있습니다. [사용법](shots/E31_사용법의횟수.png) · [두 번 다시 만든 얼굴 화면](shots/E19_두번다쓴뒤.png)
- **작은 단추와 파일 고르기.** 세로 화면에서 얼굴 풀이 물음표는 22×22, 「건의하기」 높이는 29, 판 고르기 높이는 37이었습니다(화면 기준 픽셀). 원고·얼굴 선택은 높이 55, 승인도 55, 아래쪽 탭은 49였습니다. 글자를 크게 한 사용법 화면에서 「알림 켜기」는 단어 중간에서 줄이 갈렸습니다. 문서와 소리 파일을 사진 사이에 넘겼을 때도 어떤 파일을 뺄지 안내하지 않았습니다. [큰 글자](shots/E29_큰글.png) · [여러 종류를 함께 보낸 뒤](shots/E04_다른파일섞음.png)

## 잘 되는 것

- **처음 보내기에서 연결이 멎었을 때 스스로 회복했습니다.** 사진 두 장 뒤 영상 받기만 멈추고 연결을 열어 두니 약 32초 뒤 영상만 다시 보내 한 편을 접수했습니다. 이 PC의 시험 웹앱을 전송 도중 껐다 켜도 「다시 보내기」로 이어졌습니다. [서버를 끈 뒤](shots/E10_서버꺼짐.png) · [다시 켜고 접수한 뒤](shots/E10_다시켠뒤.png)
- **답을 나중에 해도 길이 이어졌습니다.** 작업 화면을 닫았다 돌아오면 표시와 물음이 남았습니다. 원고는 두 번 고칠 수 있었고, 승인 전에는 고친 영상과 첫 영상을 번갈아 골랐습니다. 승인 뒤 같은 올리기 화면에 머물러도 캡션 복사가 켜졌고, 잘못 누른 「올림」도 취소됐습니다. [돌아온 물음](shots/E15_돌아온물음.png) · [고친 판](shots/E23_둘째판선택.png) · [캡션 복사](shots/E24_캡션복사.png) · [올림 취소](shots/E25_올림취소.png)

## 한 편을 끝까지 눌러 본 결과

보내기 → 시술 전 사진 없이 진행 → 원고 확인 → 얼굴 확인 → 편집 → 영상 판 선택 → 승인 → 캡션 복사 → 올림·취소 → 사용법 → 건의 접수 → 다음 편 보내기까지 이어졌습니다. 고친 편에서는 두 번째 판이, 같은 사진을 두 번 넣은 편에서는 첫 판이 승인됐습니다. 편집·판정과 캡션은 시험 도우미가 맡았고, 영상 재생을 누를 때는 직접 만든 색종이 영상을 사용했습니다. 실제 게시를 뜻하는 외부 동작은 없었습니다. ## 진짜 아이폰에서만 볼 수 있는 것

1. **아침에 먼저 볼 일은 보내던 화면으로 돌아오기입니다.** 사진 두 장과 큰 영상을 보내다가 화면을 잠그거나 다른 앱에 잠깐 다녀온 뒤, 몇 번째 파일인지와 다시 보내는 단추가 보이는지 봅니다. 오래 열어 둬 로그인이 풀렸다면 번호판이 뜨고 같은 묶음을 이어 보낼 수 있는지도 봅니다.
2. **사진 보관함에서 같은 세 개를 다시 골라 봅니다.** 실제 아이폰 사진(HEIC·HEIF), 클라우드에서 받아야 하는 원본, 큰 영상이 준비되는 동안 어떤 안내가 보이는지 봅니다. 앱은 파일 이름·크기·앞부분으로 받은 것을 대조합니다. 다시 고를 때 원본 이름이나 크기가 바뀌는지, 한 묶음에 같은 사진이 더 들어가는지가 남았습니다. 이 PC에서는 한글·빈칸 이름과 두 확장자 접수까지 확인했습니다. 확장자 시험에는 색종이 그림에 그 이름을 붙였습니다.
3. **완성 영상을 눌러 재생하고 사진 앱에서 열어 봅니다.** 매장에서 쓰는 보안 주소(HTTPS), 공유 창에서 사진 앱에 저장, 홈 화면에 추가, 닫힌 앱의 알림, 화면 꺼짐 방지와 실제 한글 자판이 올라올 때의 가림도 실기기에서 확인할 항목입니다.
