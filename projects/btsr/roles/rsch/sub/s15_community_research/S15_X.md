# 쓸 만한 것 다섯

1. **휴대폰에는 완성 파일과 게시글을 함께 돌려준다.** 여러 촬영물과 한 줄 요청을 받아 세로 MP4를 파일로 보내고, 전체 게시글을 따로 저장하는 공개 코드가 있다. [휴대폰 반환 코드](https://github.com/palych65/telegram-capcut-reels/blob/b3e3772db3590a52bdbbfe34658ff038f31ef217/scripts/bot.py#L421-L472)
2. **이미 찍은 장면은 편집하고, 새로 만들어야 할 장면만 생성한다.** 같은 20.4초 원본으로 네 도구가 모두 쇼츠를 완성했다. 한편 상품 사진으로 새 영상을 만든 시험에서는 5초 파일이 정상이어도 끝에서 병뚜껑이 잘렸다. [편집 비교 실험](https://github.com/intelligent-iterations/agentic-video-editing/blob/a614dc56f2e65465c924a8b089d03cf1472007f7/docs/experiment.md) · [상품 영상 시험](https://kingy.ai/production-benchmarks/)
3. **첫 편집은 맡겨도 장면 선택과 수정 자리는 남긴다.** 홍보 영상 하나를 두고 X 제작자는 한 번에 만들었다고 했고, 같은 팀의 제작 기록은 피드백 다섯 차례를 밝혔다. [X 시연](https://x.com/i/status/2099436575482425654) · [제작팀의 Hacker News 댓글](https://news.ycombinator.com/item?id=49697382)
4. **자막과 얼굴 가리기는 내보낸 화면에서 확인한다.** 음성을 제대로 받아쓰고도 자막이 빈 네모로 나온 사례가 있고, 얼굴 가리기 제작자도 동영상에서 가림 위치가 흔들려 손으로 고치는 기능을 넣었다. [자막 오류 보고](https://github.com/browser-use/video-use/issues/118) · [얼굴 가리기 사용기](https://news.ycombinator.com/item?id=48998670)
5. **혼자 쓰는 앱은 휴대폰에 저장해서 올리는 것만으로도 끝낼 수 있다.** TikTok은 자기 계정만을 위한 업로드 도구를 공개 직접 게시 심사의 부적합 예로 든다. [TikTok 직접 게시 지침](https://developers.tiktok.com/docs/en/content-sharing-guidelines)

**S15_X · X와 영어권 제작자 조사 · 2026-11-28 KST.** X는 로그인 없이 공식 공개 임베드에서 제작자 본문을 읽었다. Hacker News 글의 게시 시각은 공식 API 값에서 한국 시각으로 바꿨다. 시각 없이 날짜만 공개한 실험은 제작자가 적은 날짜를 썼다. 아래의 **상**은 원본 코드·기록이나 공식 조건으로 해당 사실을 확인한 경우, **중**은 범위가 좁은 직접 경험이나 제작팀의 단독 보고, **하**는 홍보 문구만으로 성능을 판단하는 경우다.

## 0. 처음부터 만든다면 어떤 얼개인가

**이 표본에서 반복된 얼개는 원본 파일 → 장면과 문구를 고르는 에이전트 → 편집 목록이나 코드 → 영상 파일 → 사람의 확인이다.** Video Use는 구간별 편집 목록과 FFmpeg, OpenEdit은 HTML 장면과 부분 재출력, Palmier는 편집기의 시간표를 조작하는 도구를 쓴다. 세 사례 모두 어느 장면을 어디에 썼는지 다시 열어 볼 수 있다. 전체 제작자의 사용률을 추정할 표본은 없다. **상 · 서로 다른 제작팀의 공개 구현을 대조.** [Video Use 10월 9일 판](https://github.com/browser-use/video-use/tree/43cfc566833548093455c9d4a46bd69913b7e552) · [OpenEdit 11월 24일 판](https://github.com/veedstudio/open-edit/tree/9dc3ca0f6584121f1a089c0488d925c1358cb8a7) · [Palmier 제작팀, 7월 24일](https://news.ycombinator.com/item?id=49022911)

**여섯 달 전과의 차이는 같은 제품에서 보인다.** 5월 21일 HyperFrames의 X 시연 주제는 공개 자막 모양 17종과 로컬 배경 제거였다. 10월 24일 같은 팀은 대본에서 단어를 고르면 그 시점에 그래픽을 얹고, 쉼과 군말을 지우는 편집을 공개했다. 10월 25일 변경 기록에는 중첩된 장면 안에서도 대본 단어를 잘랐다 복원하는 기능이 적혀 있다. **상 · 두 시점의 제작사 발표와 배포 기록.** 업계 전체의 변화를 뜻하는 수치는 없다. [5월 X](https://x.com/i/status/2057123793907458232) · [10월 X](https://x.com/i/status/2113670541274144802) · [변경 기록](https://hyperframes.studio/changelog)

## 3. 목소리·자막·음악

- **목소리와 자막은 따로 만들 수 있다.** RxFilm에는 Gemini·Azure 음성 합성, Whisper 계열 등의 받아쓰기, Lyria 음악이 있다. OpenEdit은 단어별 시간을 써서 자막을 영상에 입히고, 로컬 WhisperX와 서버 받아쓰기를 고르게 한다. **상 · 제작자가 공개한 11월 코드에서 확인한 선택지.** 한국어 음질이나 정확도는 따로 측정하지 않았다. [RxFilm](https://github.com/rxtech-lab/film-workflow/tree/e0be585c30779f8b6db6bfca68c921f24ce269fd) · [OpenEdit](https://github.com/veedstudio/open-edit/tree/9dc3ca0f6584121f1a089c0488d925c1358cb8a7)
- **한글 자막은 최종 영상에서 읽어 봐야 한다.** Video Use의 8월 5일 오류 보고자는 중국어 31초 영상에서 강제 지정한 글꼴 때문에 글자가 네모로 나왔고, 두 단어씩 끊은 자막이 서로 다른 발화를 합쳤다고 기록했다. 11월 28일 확인한 글꼴 수정 제안은 열려 있었다. **상 · 입력 조건·결과·수정안 공개.** 한글에서 같은 오류가 발생한다는 실측은 없다. [사용자의 재현 기록](https://github.com/browser-use/video-use/issues/118) · [수정안](https://github.com/browser-use/video-use/pull/120)
- **가게 홍보에 쓸 권리는 음원별로 확인한다.** ElevenLabs는 필요한 권리를 가진 사람이 유료 구독 중 비베타 서비스에서 생성한 음성을 상업 이용할 수 있다고 적었다. 무료 시기에 생성한 음성은 나중에 구독해도 상업 이용 대상에서 빠진다. TikTok은 사업용 게시물에 상업용 음악 보관함(CML)을 제공한다. 다른 SNS에도 낼 파일은 그 매체까지 허용된 음악을 쓰거나 음악을 뺀 파일로 돌려주면 된다. **상 · 각 서비스의 공식 조건, 11월 28일 열람.** [ElevenLabs 이용 조건](https://elevenlabs.io/docs/help-center/legal/can-i-publish-the-content-i-generate-on-the-platform) · [TikTok 음악 안내, 2025년 7월 갱신](https://ads.tiktok.com/resources/help/article/commercial-music-library?lang=en)

## 4. 사진 다듬기·얼굴 가리기·사진을 영상으로

- **상품 사진** — 2월 20일 X의 실사용자는 검은 배경에서 찍은 병 사진 한 장과 생성 결과 세 장을 비교했다. 로고와 병의 글자가 달라졌다고 보고했다. 배경 제거·노출 보정만 필요한 사진은 상품 원본을 살릴 수 있다. Photoroom의 공개 API 단가는 배경 제거 장당 0.02달러, 고급 편집 장당 0.10달러이며 월 단위 결제다. **중 · 실물 한 제품의 직접 경험. 상 · 공급사 가격표.** [X 사용기](https://x.com/i/status/2024611612531826795) · [사진 편집 가격](https://www.photoroom.com/api/pricing)
- **얼굴 가리기** — Faceblind 제작자는 중거리 등반 영상을 Chrome·Firefox로 시험했다. 얼굴 검출이 빗나가면 자세 검출로 보완했고, 흔들리는 가림 영역을 손으로 수정할 수 있게 했다. 정지 사진과 영상 모두를 파일로 처리하는 deface도 있다. 검은 사각형을 쓸 수 있고, 기본값에서는 소리까지 빠지므로 원래 말소리를 살릴 작업은 음성 결과도 확인해야 한다. **중 · 7월 22일 직접 시험, 환경이 제한됨. 상 · deface의 공식 기본값.** [Faceblind 제작기](https://news.ycombinator.com/item?id=48998670) · [deface 설명](https://github.com/ORB-HD/deface)
- **얼굴 바꾸기** — InsightFace는 코드에 MIT 허가를 주지만 공개 사전학습 모델은 비상업 연구용으로 안내하고, 얼굴 교체 모델의 이용 허가는 별도 문의하도록 적었다. 가림이 목적인 홍보물에 얼굴 교체를 쓰면 모델 이용 권리와 결과 얼굴 검토까지 일이 늘어난다. **상 · 제작팀 이용 조건, 11월 28일 열람.** [InsightFace 모델 조건](https://github.com/deepinsight/insightface#license)
- **사진에서 움직임 만들기** — 9월 27일 공개한 실험은 병 전체가 계속 보이게 해 달라는 사진 한 장으로 Gen-4.5 세로 영상 한 개를 만들었다. 길이와 재생 검사는 통과했지만 4.5초 지점에서 뚜껑이 화면 밖으로 나갔다. 잔액 감소분은 60크레딧, 당시 환산 0.60달러였다. 원본 위에 천천히 확대·이동 효과만 얹는 방법은 상품을 새로 그릴 필요가 없다. **중 · 원본·프레임·잔액 관찰을 공개한 1회 시험, 판독은 에이전트가 했다.** [시험 결과](https://kingy.ai/production-benchmarks/) · [확대·이동 출력 코드, 5월 11일](https://github.com/220-organization/open-smm/blob/efbb469938d3a8e9f8020d01342063275fbd93e9/app/services/video_renderer.py#L25-L49)

## 5. 에이전트 수·사람이 보는 자리·다시 하기

**한 명이 쓸 앱이라면 편집 방향을 승인하고 완성본을 다시 열 수 있어야 한다.** Video Use는 원본마다 받아쓴 글과 단어 시간을 남기고, 애매한 구간에서만 대표 화면과 소리 파형을 본다. 사람이 편집 방향을 승인하면 에이전트가 구간 목록을 만들어 영상을 출력한다. 잘린 경계에서 문제를 찾으면 세 번까지 고쳐 다시 출력하며, 다음 작업을 위해 기록을 남긴다. 애니메이션 제작은 여러 에이전트에 나눈다. **상 · 10월 9일 공개 작업 순서.** 모든 오류를 찾아낸다는 증거는 없다. [Video Use](https://github.com/browser-use/video-use/tree/43cfc566833548093455c9d4a46bd69913b7e552)

같은 영상도 필요한 사람 손은 다르다. 9월 14일 OpenEdit 시연은 웹사이트와 브랜드 지침으로 시작했지만 제작팀은 피드백 다섯 차례를 따로 밝혔다. 11월 5일 Kino 창업팀은 자체 출시 영상을 만들 때 본인 쪽 에이전트만 다섯 이상이 같은 시간표를 나눠 편집했고 사람도 직접 미세 조정했다고 썼다. 9월 6일 다른 제작자는 받아쓰기만 보고 자른 영상의 타이밍이 좋지 않아 사람이 자른 지점을 에이전트에 돌려주는 도구를 만들었다. **중 · 각자 자신의 작업을 보고했으며 작업 종류와 분량이 다르다.** [OpenEdit 제작 댓글](https://news.ycombinator.com/item?id=49697382) · [Kino 제작기](https://news.ycombinator.com/item?id=50368804) · [Fast Cut 제작기](https://news.ycombinator.com/item?id=49580689)

## 6. 휴대폰으로 보내고 받고 올리는 길

1. **여러 파일과 요청문** — 앞의 Telegram–CapCut 방식은 Mac이 편집하고 휴대폰은 자료를 보내고 결과를 받는다. 서버가 반환한 MP4는 내려받을 수 있고, 초안을 고치려면 편집기와 동기화가 필요하다. 기본 Telegram 봇 API는 파일 받기 20MB, 보내기 50MB 한도다. 이 예제는 자체 봇 API 서버를 두며 공식 문서상 이때 내려받기 크기 제한이 풀리고 업로드는 2,000MB까지다. **상 · 6월 2일 코드와 11월 28일 공식 한도 대조.** [예제](https://github.com/palych65/telegram-capcut-reels/tree/b3e3772db3590a52bdbbfe34658ff038f31ef217) · [기본 한도](https://core.telegram.org/bots/faq#how-do-i-download-files) · [자체 서버 한도](https://core.telegram.org/bots/api#using-a-local-bot-api-server)
2. **사진 한 장과 게시 승인** — 자체 서버용 Open SMM은 사진을 확대·이동하거나 동영상을 잘라 1080×1920 MP4를 만든다. Telegram에 영상과 TikTok·Instagram용 글을 보여 주고 승인·재생성·거절을 받는다. 코드상 여러 파일이 와도 정렬 후 첫 파일만 쓴다. Instagram 게시 유형 기본값도 일반 게시물(`post`)이어서 원하는 릴스로 발행되는지는 연동별 확인이 필요하다. **상 · 5월 11일 코드에서 입력 선택·반환·기본값 확인. 외부 계정의 게시 성공은 미확인.** [첫 파일을 고르는 줄](https://github.com/220-organization/open-smm/blob/efbb469938d3a8e9f8020d01342063275fbd93e9/app/jobs/job_runner.py#L100-L114) · [승인·게시 설명](https://github.com/220-organization/open-smm/tree/efbb469938d3a8e9f8020d01342063275fbd93e9)
3. **폰에서 마지막 게시** — 개인용으로는 MP4와 글을 받아 SNS 앱에서 마지막 게시를 누르는 경로가 짧다. 별도로 TikTok의 승인된 업로드 연동도 알림을 보내고 사용자가 TikTok 안에서 편집·게시를 마치는 흐름을 제공한다. **상 · 플랫폼 공식 명세, 11월 28일 열람.** [TikTok 업로드와 알림](https://developers.tiktok.com/docs/en/content-posting-api-get-started-upload-content)
