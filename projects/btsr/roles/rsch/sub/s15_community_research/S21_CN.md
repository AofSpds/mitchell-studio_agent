## 쓸 만한 것 다섯

1. **받은 촬영분은 '글로 바꿔서' 편집을 판단하고, 자르기 · 합치기는 FFmpeg로** — 낱말마다 시각이 붙은 받아쓰기로 헛 컷 · 말버릇을 고르고, 필요할 때만 장면 그림 · 파형을 봄(video-use). 영상을 통째로 모델에 보이지 않아 값이 싸고 안정적. 중국 파이프라인(Pixelle-Video · Huobao · DirectorAI)도 끝은 모두 FFmpeg.
2. **줄은 정해 두고, 판단 자리에만 모델 + 다른 모델 하나가 검토 + 사람 확인 두 번(대본 · 완성본)** — '모델은 제 것을 못 평가한다 → 비평 모델을 두니 나아졌다'(DirectorAI · 직접 6주 만든 글). 다시 하기는 장면 하나 단위(LibTV · OpenMontage). 참고 구현은 Pixelle-Video(Apache-2.0 · 별 약 3만).
3. **모자란 장면만 생성 모델로, 종량 API + 한 편 상한** — 사진 → 5 – 10초 조각(Seedance 2.0 Mini 720p 약 0.5위안/초 = 5초 약 2.5위안). 구독 포인트는 갑자기 깎임(即梦 4월) · 10초쯤 조각은 믿을 만하고 1분 넘는 통째 생성은 아직 아님.
4. **목소리는 CosyVoice 3(Apache-2.0 · 한국어 됨) 같은 허가가 분명한 것으로, edge-tts는 쓰지 않음** — edge-tts는 공식 API가 아니고 중국에서 막힘 · 403이 실제로 남. IndexTTS2는 한국어 안 되고 B站 허가(Apache 아님). 자막은 낱말 시각 받아쓰기(WhisperX · FunASR).
5. **휴대폰 앞문은 이미 쓰는 메신저 봇, 돌려줄 땐 미리보기 + 주소, 올리기는 사람이** — 飞书 봇은 WebSocket 긴 연결이라 집 PC · 작은 서버에 두어도 바깥 주소가 필요 없음(OpenClaw · 飞书 공식 글). n8n 틀은 주제 · 대본 · 영상 세 번 확인. **완전 자동 올리기는 小红书가 2026-03-10부터 계정을 막는 꼴**이고, 손님 얼굴은 '바꾸기'가 아니라 '가리기'만(Seedance도 실제 얼굴 참고를 막음).

- **pyJianYingDraft** (github.com/GuanYixuan/pyJianYingDraft · Apache-2.0 · 별 약 5.1천 · 만든 사람의 README로 확인 · 믿음 상): 파이썬으로 剪映 초안(`draft_content.json`)을 씀 — 트랙 · 영상/소리/글자/스티커 조각 · 키프레임 · 효과 · 필터 · 마스크 · 크로마키 · SRT 자막. 있던 초안을 틀로 읽어 소재 · 글자만 바꾸는 '틀 모드'도 있음.

- **공통 한계(믿음 상 — 위 README 둘이 같은 말):** 剪映은 API를 열지 않음 → 남이 풀어 낸 초안 구조에 기대고 **판이 오르면 깨짐** · **렌더는 결국 윈도 PC의 剪映 앱 + 화면 자동 조작 또는 남의 유료 클라우드** · VIP 기능에 걸림. 즉 '파일로 편집'처럼 보이나 **마지막 한 걸음은 화면을 대신 누르는 방식**이다.

**나. 扣子(Coze · 바이트댄스의 노코드 에이전트 판) 워크플로 + '剪映小助手'** — 소개 · 강좌 글이 아주 많음

- 직접 겪은 고장: **플러그인과 小助手가 서로 다른 곳에서 만든 것이면 초안 내려받기가 실패** · 小助手의 '剪映 경로'를 剪映 초안 폴더와 맞춰야 함 · '1분 만에 완성 · 사람 손 0' 같은 말은 대부분 글쓴이 자랑이고, 실제로는 **剪映에서 박자 · 필터를 사람이 손보고** 올림.

## 4. 사진 · 얼굴

**가. 얼굴 가리기(打码)** — 중국 쪽은 '앱 · 온라인 도구'가 많고 오픈소스 완제품은 드묾

- 스스로 짜는 길: OpenCV + face_recognition(또는 YOLO 얼굴 검출) → 화면만 떼어 얼굴마다 가우스 흐림 · 모자이크 → 소리 다시 붙이기(CSDN · 博客园 강좌 · 2022년 글이라 오래됨 · 믿음 중). '검출기는 아무것이나 바꿔 끼울 수 있다'가 요지.
- 검색에 '오픈소스 + 영상 일괄 가리기' 완제품은 안 걸림(못 본 것).

**나. 얼굴 바꾸기 · 실제 사람 얼굴을 넣어 영상 만들기 — 막히는 쪽으로 감(믿음 상 · 중)**
- **Seedance 2.0은 실제 사람 얼굴이 든 참고 그림을 막음** — 바로 넣으면 '개인 정보 든 그림' 오류(`InputImageSensitiveContentDetected.PrivacyInformation`)로 거절. 실제 사람(연예인 · 모델 · 본인)은 **얼굴 인식 본인 확인(活体扫脸认证)을 거쳐 소재함에 넣은 뒤** 그 번호로만 부름 · 가상 인물은 바로 됨 (API 중계 회사 문서 docs.apiyi.com/faq/seedance2-asset-face-reference — 공식 문서 아님 · 믿음 중). **나. 겪은 사람들의 말(교훈)**
- **모델은 자기 것을 잘 못 평가한다 → 다른 모델을 비평가로 두니 나아졌다**(DirectorAI). **입출력을 틀에 맞춘 것**(JSON 대본 · 고정 해상도 · 길이)이 시험을 가능하게 했다. 쓰는 사람들은 일관성보다 **음악과 진행 표시 화면**을 더 칭찬했다.
- **일관성(인물이 장면마다 얼굴이 바뀜)** 이 가장 큰 벽 — DirectorAI는 '못 풀었다', V2EX 실험자도 같은 문제(첫 · 끝 장면 지정 · 인물 참고로 막음). 막는 방법: 인물 세 면 그림을 모든 장면의 참고로(DirectorAI · LibTV) · 인물마다 LoRA(텐센트 클라우드 글 — SD 1.5 시절 방식이라 오래됨) · 생성 전에 닻을 정해 두기(LibTV).
- **다시 하기는 '통째로'가 아니라 '장면 하나'** 단위(LibTV · DirectorAI · OpenMontage 모두). 뽑기(抽卡) 값이 가장 큰 비용이라는 말이 여러 글에 나옴.
- **긴 작업은 '받았음 → 뒤에서 물어보기'**: 생성 API는 몇 분이 걸려 웹훅은 바로 답하고 Wait + 조회를 되풀이(n8n 틀 · lazycat 강좌). V2EX 영상 사이트 개발자(v2ex.com/t/1164872 · 2025-10)가 겪은 고장: 공급자마다 상태 이름 · 결과 주소 칸 이름이 다름(resultUrl · mediaUrl · resourceUrl) · 서명 주소가 시간 지나 401 · 긴 작업이 거짓으로 '끝남' → **공급자 답을 하나로 맞추는 층 · 조회 간격을 점점 늘리기 · 502/429에 다시 하기**.
- LibTV 쪽 기자 판단: '한 문장 → 완성 영상'은 아직 기대에 못 미침 · **10초쯤 조각은 믿을 만하고 1분 넘는 것은 아직 비현실**.
