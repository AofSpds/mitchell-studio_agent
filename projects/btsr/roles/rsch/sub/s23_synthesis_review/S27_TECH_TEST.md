## 1. 결론과 나누는 기준

**첫 영상 시험으로 B1(편집표 → FFmpeg → 한글 자막·소리가 있는 15초 영상)을 권한다.** 길 1의 가장 작은 굽기·검사·이어 하기 고리를 확인할 수 있다. 다만 현재 FFmpeg와 ffprobe는 PATH에 없으므로 준비 허락이 먼저다. 지금 설치 없이 할 수 있는 후보는 A0의 편집표·상태 검사까지다.

- A는 현재 확인된 도구로 키·추가 사용료 없이 오늘–내일 착수할 수 있는 후보다. 이번에는 A도 실행하지 않는다.
- B는 키·돈·한알의 추가 허락 가운데 필요한 조건이 남은 후보다. **B라고 모두 유료인 것은 아니다.** 설치·모델·소재 준비가 남은 무료 시험도 B로 둔다.
- B1–B3은 준비를 허락받고 도구·소재가 갖춰지면 각 반나절–하루 범위의 무키·무과금 후보다. 모두를 하루에 끝낸다는 뜻은 아니다.
- ‘무료’는 API·추가 소프트웨어 사용료 기준이다. 전기·기존 기기·작업 시간까지 0원이라는 뜻이 아니다.
- 모든 입력은 직접 만든 것 또는 재사용이 허용된 공개 소재로 한정한다. 손님·남의 얼굴이 든 사진·영상은 제외한다. 실존 인물 기반 얼굴 합성도 쓰지 않는다.
- 장면 선택 모델·목소리·받아쓰기를 한꺼번에 붙이지 않는다. 먼저 손으로 고정한 편집표로 굽기를 재현한 뒤 판단 자리를 더한다(종합 140–143·152; S19 80·83).
- 시험 코드·소재·결과를 둘 자리는 후속 의뢰에서 정한다. 이 기억 저장소에는 이번 후보 문서만 둔다.

## 3. B — 키·돈·한알 허락이 있어야 되는 것

### B1. 첫 권고 — FFmpeg로 15초 한 편과 실패 뒤 이어 하기

- **물음:** 고정 편집표대로 한글 글자·소리·장면을 정확히 굽고, 결과를 검사한 뒤 끝났다고 할 수 있는가?
- **됨의 기준:** 1080×1920·30fps·450프레임의 MP4, 마지막 프레임까지 해독 오류 0건. 한글 시험 문구 6개가 네모·잘림 없이 6/6 읽히고, 화면 밖 글자 0개. 3개 기준 시점의 표시와 시험음 어긋남 1프레임 이하, 의도한 소리 구간의 무음 0건.
- **반복 기준:** 같은 입력 3회에서 장면 순서·글자·길이가 같음(파일 전체 해시 일치는 요구하지 않음). 굽기 직전 가짜 실패 1회 뒤 재개할 때 저장한 입력을 재사용. 두 작업에 같은 장면 번호를 써도 자막 섞임 0건. 무음·짧게 잘린 결과는 완료 판정에서 모두 탈락.
- **넣을 것:** 직접 만든 도형 사진 3장, 시험음, 직접 쓴 6개 문구(받침·숫자·원 기호·띄어쓰기·두 줄 문장 포함), 사람이 고정한 편집표. 얼굴·배경 음악·TTS·LLM 없음. 한글·띄어쓰기 파일 경로도 한 번 포함한다.
- **필요한 것:** FFmpeg·ffprobe와 한글 글꼴 준비 허락. 자막 필터를 지원하는 실행판과 글꼴의 사용 조건 확인; 이 PC에 있는지는 미확인. Node로 순서를 묶고 CPU로 굽는다. 키·API 사용료·GPU 없음; Python·magick은 필수로 두지 않는다.
- **때 어림:** 준비가 순조로우면 3–6시간. 실행판·글꼴을 확보하지 못하면 시작하지 않는다.
- **근거:** 종합 79·104·109–111·140·174·176; S15 39; S16 24; S17 30·38; S18 34–35; S19 80·112; S22 46·73·100·103.
- **못 하면 남는 것:** 이 윈도 환경의 기본 굽기·한글 표시·소리 보존·재시작 가능성. 통과해도 목소리 품질·받아쓰기·장면 선택·얼굴 검출은 모른다.

### B2. 같은 편집표로 Remotion·HyperFrames 견주기

- **물음:** B1의 굽기보다 움직이는 글자·화면 틀에서 얻는 이득이 준비·수정 품을 보상하는가?
- **됨의 기준:** 같은 15초 입력과 배치 명세로 두 도구 모두 B1의 길이·소리·한글 검사를 통과. 문구 한 줄 수정 뒤 다른 장면 변화 0건. 첫 준비 시간·3회 굽기 시간·오류 수·손으로 고친 횟수·실제로 내려받은 양을 각각 기록한다.
- **넣을 것:** B1 소재·편집표, 직접 정한 글자 이동 한 가지. 코딩 에이전트가 새로 장면을 고르는 변수를 넣지 않는다.

- **못 하면 남는 것:** 이 PC에서의 도구 선택 근거. 한 영상·평가자 한 명의 기존 점수로 전체 우열을 결정할 수 없다. S15의 HyperFrames Studio와 S19의 HeyGen 엔진 조건도 섞지 않는다.

### B3. 휴대폰 HDR 입력을 SDR 결과로 굽기

- **물음:** HDR 촬영본 때문에 끊기거나 색이 무너지는가?
- **됨의 기준:** 10초 SDR 1개와 HDR 1개를 끝까지 해독·출력, 오류 0건·길이 오차 1프레임 이하. SDR 결과의 색 정보와 시작·중간·끝 세 화면을 확인하고, 비교 화면 3/3에서 검게 사라짐·심한 밝기 날림이 없다는 사람 판정을 기록한다.
- **넣을 것:** 사람이 없는 물건·색판을 직접 찍은 SDR/HDR 짝. HDR10+는 실제 해당 촬영본을 확보했을 때만 시험했다고 적는다. HDR 표시만 바꾼 파일로 대신하지 않는다.
- **필요한 것:** B1 도구·관련 해독/색 변환 기능, 직접 찍은 소재 준비 허락. CPU로 시도; 키·API 값·전용 GPU 없음. 소재·휴대폰·화면의 HDR 지원은 이번에 확인하지 않음.
- **때 어림:** 소재 확보 뒤 2–4시간.
- **근거:** 종합 182; S18 6·64의 HDR10+ 내보내기 실패. 윈도에서 같은 원인이라는 결론은 아직 없다.
- **못 하면 남는 것:** 실제 휴대폰 원본 수용 범위. 통과해도 다른 기종·코덱이나 정확한 색 재현까지 보장하지 않는다.

### B4. 한국어 받아쓰기와 자막 시각

- **물음:** 가격·가상 상호·상품명을 얼마나 틀리며, 말과 자막을 얼마나 어긋나게 잡는가?
- **됨의 기준:** 정답을 먼저 쓴 20문장을 조용한 조건과 잡음 조건으로 각각 시험. 문자 오류율[(대치+삭제+삽입)/정답 글자 수], 핵심값 20개의 정답 수, 문장 경계 시각 오차를 기록. 임시 목표는 조용한 조건 문자 오류율 5% 이하·경계 오차 95백분위 0.2초 이하; 두 조건 모두 메모를 적용한 최종 가격·상품명 오류 0개. 원래 받아쓰기의 오류를 교정 성과와 따로 남긴다.
- **넣을 것:** 개인정보 없는 가상 광고문을 사용 허락된 직접 녹음으로 만들고, 직접 합성한 잡음을 더한 짝. 정답 문구·시각은 사람이 작성. 공백·숫자 표기 비교 규칙도 먼저 고정한다.
- **필요한 것:** faster-whisper 또는 Whisper 계열 CPU용 실행 환경·한국어 모델 준비 허락; 필요하면 WhisperX 정렬을 별도 비교. 지정 Python 3.13에서 설치되는지는 미확인. 로컬 CPU판은 키·API 값 없음; GPU 전용판 선택 시 맞는 GPU가 필요하므로 현 상태에서는 보류.
- **때 어림:** 환경·음성 확보 뒤 반나절–하루. 한국어 정렬 모델이 없거나 CPU판이 안 맞으면 그 항목은 미시험으로 둔다.
- **근거:** 종합 111·176·193; S15 38; S16 40; S17 39; S18 43·85·93; S19 111; S21 112–114; S22 115.
- **못 하면 남는 것:** 한국어 오류율·시각 오차·수정 시간. 공개 사례의 ‘자막이 됨’으로 가격 정확도를 대신할 수 없다.

### B5. 한국어 목소리 두 종류를 같은 문장으로 듣기

- **물음:** 숫자·단위·기호·가상 상품명을 일관되게 읽고, 30초 영상에 쓸 만한가?
- **됨의 기준:** 시험문 12개를 원문/읽기용으로 다듬은 문장으로 나눠 각각 2회 합성. 핵심 발음 20항목 정답 수·발음 바뀜 수·실제 음성 길이·끝 잘림·생성 시간을 기록. 다듬은 문장의 핵심 발음 오류 0개, 끝 잘림 0개, 이름을 가리고 들은 자연스러움 평가 중앙값 4/5 이상을 임시 목표로 삼는다. 한 사람 평가라는 한계도 적는다.

- **필요한 것:** 우선 Supertonic 3 로컬판과 Typecast를 견줄 후보로 둔다. 전자는 실행 환경·모델 준비·조건 검토 허락, 후자는 키·사용량/플랜 비용·한알의 지출 허락이 필요하다. 로컬판은 CPU 구동 가능 판 확인 뒤; 클라우드는 로컬 GPU 불필요. Gemini TTS·CosyVoice 3는 두 번째 후보이며 아직 윈도 준비 조건을 모른다.
- **때 어림:** 환경·키가 준비된 뒤 3–6시간. 가입·허락 대기는 별도. 무료 계정이 이미 있다는 전제를 두지 않는다.
- **근거:** 종합 125·193; S16 41; S18 44·79; S20 74·164; S21 103·254; S22 110–115. CosyVoice 허가는 S21이 README·모델 카드만 봤고 LICENSE 원문을 못 봤다는 단서까지 유지한다.
- **못 하면 남는 것:** 한국어 청취 품질과 읽기용 문장 손질 효과. 무료 목소리의 평가 성공이 홍보물 이용 허락을 뜻하지 않는다. Kokoro 한국어 지원은 글끼리 엇갈리고 edge-tts 상업 사용 근거는 확보되지 않아 첫 비교에서 뺀다(종합 125; S17 40; S20 75–76).

### B6. deface가 가상 얼굴을 놓치는 프레임 세기

- **물음:** 잠깐 드러나는 얼굴과 엉뚱한 가림을 잡아낼 수 있으며, 소리도 남는가?
- **됨의 기준:** 정면·옆면·작은 얼굴·가림·빠른 이동·화면 출입의 6조건, 각 5초·30fps를 사람이 전 프레임 확인. 분모는 정답으로 표시한 프레임별 얼굴 수, 분자는 가려야 할 얼굴 영역이 남은 수. 자동 단계의 누락률·연속 노출 최장 프레임 수·잘못 가린 수·검토/수정 시간을 기록. 사람 수정 뒤 해당 표본의 노출 0개와 시험음 보존을 통과선으로 둔다.
- **넣을 것:** 직접 만들었거나 재사용 허락이 확인된 **비실존 합성 얼굴** 소재만. 그런 소재를 확보하지 못하면 보류한다. 지금 소재를 찾거나 만들지 않았다.
- **필요한 것:** deface·의존 프로그램·모델 준비 허락, B1 도구, 표본 준비. 소리 보존 설정을 명시한다. S19에 CPU 가능이라고 적혀 있으므로 GPU 필수로 잡지 않는다. 키·API 사용료 없음.
- **때 어림:** 환경·소재 준비 뒤 반나절–하루. 900프레임 전수 검토 시간을 따로 잰다.
- **근거:** 종합 82·112·178·194; S15 45; S18 50–51; S19 137; S20 83–84. S18의 모자 쓴 행인 누락은 2020년 구형 편집기 사례라 deface의 현재 실패율로 옮기지 않는다.
- **못 하면 남는 것:** 표본 누락·깜빡임·소리 유실·사람 수정 부담. **합성 얼굴의 시험을 통과해도 실제 손님 얼굴 누락률은 계속 모른다.** 드문 노출을 1초 간격 화면 몇 장만 보고 통과시키지 않는다.

### B7. 다시 하기·검토까지 넣은 한 편 값

- **물음:** 길 1의 한 편에 실제로 얼마가 청구되고 사람이 몇 분을 쓰는가?
- **됨의 기준:** 같은 범위의 30초 영상 3편에서 최초 제작·문구 수정·저장 뒤 재개를 구분. 단계별 모델명·호출 수·사용량·청구액·소요 시간·검토/수정 분을 빠짐없이 기록하고 공급자 사용 명세와 대조. 저장된 유료 단계의 불필요한 재호출 0회, 승인된 총상한 초과 0회. 청구 반영 전에는 추정치라고 표시한다.
- **넣을 것:** 직접 만든 얼굴 없는 사진·클립·가상 메모·시험 대본. 앞 후보를 통과한 부품만 연결한다. 새 영상 생성·음악 구독·SNS 올리기는 포함하지 않는다.
- **필요한 것:** 선택한 판단 모델·TTS의 키와 한알이 정한 예산 상한, 지출 허락. B1 및 필요한 B4·B5 준비. 키 값은 기록하지 않는다. 로컬 CPU+클라우드 조합이면 GPU 불필요.
- **때 어림:** 준비 뒤 4–8시간; 최종 청구 대조는 명세가 반영될 때까지 별도 대기.
- **근거:** 종합 27·110·129·184·194; S15 65; S18 79·93; S22 39–40·45·83·168–169.
- **못 하면 남는 것:** 실제 변동 청구액·실패 비용·검토 부담. API 정가 환산액, 실제 추가 청구액, 월 기본료를 각각 적는다. 사람 시간은 분으로 남기고 시간당 값을 정한 경우에만 비용으로 환산한다. 3편으로 여러 달 운영비를 일반화하지 않는다.

## 4. 첫 시험을 B1로 권하는 까닭과 남는 물음

1. 편집표·한글 자막·소리·완료 검사·단계 재개를 한 편에서 함께 확인한다. 한국어 자막 문제는 글꼴뿐 아니라 자막 필터 부재·경로·길이·작업 간 결과 섞임도 있다(S18 34–35; S22 46·73·103).
2. CPU와 고정 입력으로 시작하므로 GPU 확인·키·새 장면 생성 없이 원인을 좁힐 수 있다. A0의 편집표 검사를 B1의 앞단에 붙인다. ffmpeg-skill은 윈도 검증이 덜 됐다고 적혀 있어 첫 시험의 필수 의존으로 삼지 않는다(종합 79; S19 80).
3. B1 준비를 허락받지 못하면 A0까지만 별도 실행 후보로 남긴다. **현재 상태에서 오늘 바로 MP4를 만들 수 있다고 판정하지 않는다.**
4. 종합 193–194의 빈칸은 한글 자막=B1·B2, 한국어 받아쓰기=B4, 한국어 목소리=B5, 얼굴 가림 표본 누락=B6, 실제 한 편 값=B7로 대응한다. 실제 손님 얼굴 누락률·여러 달 운영 기록은 이번 허용 범위의 짧은 시험으로 풀리지 않는다.
5. 종합 195의 여러 에이전트 비교와 196의 휴대폰 앱 운영은 이번 첫 시험 밖이다. 길 1 전체의 무인 제작 품질을 B1 통과만으로 주장하지 않는다.
