- 위 장부 틀은 묶음 129줄의 필드·순서를 유지함. `at`·`recorded_at`에는 같은 전송 직전 KST 시각과 `+09:00`, `model`에는 화면에서 본 값을 나중에 채움. 지금의 시각·모델로 미리 채우지 않음.
- 같은 임무가 장부에 있으면 먼저 기존 대화의 전송 상태를 확인함. 새 건만 전송 직전에 UTF-8·LF 한 줄로 덧붙이고, 보낸 글은 해당 코드 블록 안쪽만 원문 그대로 사용함(묶음:106–110·129).
- 답 파일 맨 위에 주제 번호·대화 주소·모델 표시·끝난 KST 시각을 남김. 답 전문의 표·인용·링크와 첫 줄·마지막 문단을 대조하며 전송·완료 시각, 두 때 모델 표시와 한도 안내도 남김(묶음:111–114·128).
- 불분명한 전송은 다시 누르거나 장부를 고치지 않음. 한도·로그인·보안·허락 창에서는 멈추고 정해진 담당에게 상태를 알림. ‘미첼 스튜디오 · 미P번호 · 보냄 / 받음 / 막힘’ 보고도 실제 관찰 뒤의 일임(묶음:115–118·130–132·149).

| 미P1 ↔ 미P4 | 촬영본 입력과 출력 | 미P1은 사용 기록, 미P4는 공개 구현의 입력 경로. 코드 존재와 반복 사용을 서로 대신하지 않음. |

- 물음 코드 블록에는 키·비밀값·실제 사람 이름·연락처·고객 기록·얼굴 사진·봉인/평가 자료·내부 문서 통째·주인의 이름/메일/계정·내부 경로를 넣지 않음. 프로젝트 표제 외 가게 이름·업종 세부도 넣지 않음(의뢰서 S33 제외 항목; 묶음:131).
- 길 선택과 첫 결과 선택은 공개 조사가 대신 결정하지 못함. 모든 공백을 풀어야 선택할 수 있다는 뜻도 아님(한 장:39–40·179–180; S30:93–94·108).
- 커뮤니티 조사와의 대조는 지정된 한 장 0·5번 칸의 요약에 한정함. 1번 칸 자체와 바탕 원문은 허용된 읽기 범위 밖이라 다시 열지 않음(한 장:19–35·175–178).
- 못 한 것: S35·S36·S37 결과와 대조, 외부 원문·현재 서비스 조건·실제 모델·남은 한도 확인, 전송과 답 회수. 이번 읽기·쓰기 범위 밖이거나 전송 전의 후속 단계이며 권한 거부는 없었음.
- 수행 범위: 이 파일만 작성. 웹·브라우저·프로챗을 열지 않았고 답 폴더 생성·장부 쓰기·설치·커밋·push를 하지 않음.
