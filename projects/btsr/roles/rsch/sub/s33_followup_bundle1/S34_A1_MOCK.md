## 4. 길 1 설계에 넘길 것 — 읽은 이의 판단

1. 편집표에는 **꼴의 판·작업 번호·내용 판·가짜/실제 파일 번호 목록·원본 길이·장면 번호·원본 시작·사용 길이·편집 시작·자막**이 필요하다. 이 시험의 3장면 고정·빈틈 금지는 시험 조건이며 제품 요구로 확정하지 않는다(`validator.mjs:41–76`).
2. 승인은 **작업 번호 + 내용 판 + 표 전체 해시**에 묶는다. 같은 판 번호라도 내용이 달라지면 예전 승인을 적용하지 않는다(`results.txt:33–36`).
3. 단계 기록은 **작업 번호·내용 판·표 해시·단계·시도 번호·요청 UUID·대기/실행중/완료·결과 해시·한국 시각**을 가진다. 완료 결과와 완료 상태를 같은 저장 단위에 둔다(`workflow.mjs:23–30,83–93,113–131`).
4. 재개는 기록을 다시 읽어 완료 단계를 건너뛰고, 실행 중인 단계는 기존 요청을 유지한다. 새 호출이 필요한 경우는 미완료의 명시적 재시도로 구별한다(`results.txt:37–49,67–68`).
5. 응답은 작업·판·표 해시·단계·현재 시도·요청 번호를 모두 맞춘다. 끝난 시도의 늦은 응답은 현 결과를 덮어쓰지 않게 한다(`results.txt:50–64`). 가짜 결과 전체 대조를 실제 영상의 의미 검증으로 옮겨 읽어서는 안 된다.
6. 실제 외부 호출을 붙일 때는 공급자의 중복 요청 방지·결과 조회와 저장 중단 구간을 별도 시험한다. T01 통과로 실제 재결제 방지를 확정하지 않는다(S30:50,80; `results.txt:73`).
