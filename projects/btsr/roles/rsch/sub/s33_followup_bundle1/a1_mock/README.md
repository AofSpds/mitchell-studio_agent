# T01 편집표·단계 기록 연구 모형

실제 사진·영상·음성·사람·외부 호출을 사용하지 않는다. Node 내장 기능만 쓴다.
모든 편집표는 `fixtures.json`에 손으로 썼다. 정상 3개, 오류 10개이며 각각 3장면을 기본으로 한다.

## 편집표 꼴

- `schemaVersion`: 1. `jobId`: 작업을 구별하는 영문·숫자·밑줄 번호. 한 묶음에서 중복 금지.
- `revision`: 1 이상의 정수. 승인과 단계 요청은 이 판 번호와 편집표 전체 SHA-256에 묶는다.
- `assets`: 가짜 파일 목록. `assetId`와 양의 정수 `durationMs`만 있다. 실제 파일 경로가 아니다.
- `scenes`: 정확히 3개. `sceneId`, `assetId`, `sourceInMs`, `durationMs`, `timelineStartMs`, `caption`.
- 모든 시각은 정수 밀리초. 시작은 0 이상, 길이는 양수, 원본 범위 밖·시간표 겹침·빈틈은 거부한다.
- 번호 중복·없는 파일 번호·빠진 칸·알 수 없는 칸을 거부한다. 자막은 가상 문구이며 빈 문자열을 거부한다.

## 검사와 기록

`validator.mjs`는 편집표와 작업 번호 중복을 검사한다. `fixtures.json`의 오류마다 예상 오류 코드가 다르다.
`workflow.mjs`는 `edit → captions → final_marker`를 실행하며 실제 작업 대신 요청마다 `execute` 기록을 남긴다.
기록에는 작업 번호·판·표 해시·단계·시도 번호·요청 UUID·승인·완료 결과·한국 시각이 있다.
상태를 임시 파일에 쓴 뒤 같은 폴더에서 이름을 바꾼다. 재개는 파일을 새 인스턴스로 다시 읽는다.
완료 단계는 건너뛴다. 실행 중인 단계는 재개만으로 새 호출을 만들지 않고 기존 요청을 돌려준다.
명시적 재시도만 미완료 단계의 시도 번호와 요청 UUID를 바꾼다. 예전 요청의 응답은 거부한다.
같은 표의 승인은 한 번만 저장한다. 다른 승인 번호로 다시 승인해도 실행을 더 만들지 않는다.
응답의 작업·판·표 해시·단계·시도·요청 UUID와 가짜 결과의 출처를 대조한다.

## 실행

저장소 루트에서 다음 한 명령을 실행한다.

```powershell
& 'C:\Users\ms1pk\DevEnvBackup-tools\node-v24.22.0\node-v24.22.0-win-x64\node.exe' 'projects/btsr/roles/rsch/sub/s33_followup_bundle1/a1_mock/run.mjs'
```

`run.mjs`가 실제 assertion을 실행하고 명령·한국 시각·통과/실패 수·측정 근거를 `results.txt` 하나에 남긴다.
시험 중의 상태 파일은 이 폴더 바로 아래에 고유 임시 폴더를 만들어 쓰고, 종료할 때 그 폴더만 지운다.
두 중단은 완료 상태를 저장한 직후 예외로 흉내 낸다. 강제 프로세스 종료·전원 차단·저장 중 손상은 시험하지 않는다.
이 연구 모형은 실제 영상·청구·외부 서비스·여러 프로세스/컴퓨터의 동시 실행을 증명하지 않는다.
특히 외부 작업 실행과 상태 저장 사이의 중단에서 중복 과금이 없다는 보장은 하지 않는다.
